# ADR-027. Секретарь: Сара в боте отвечает через Claude CLI с инструментами ядра

- Статус: предложено (задача от Бориса через сессию разработки 28.10.2026; Борис может оспорить)
- Дата: 28.10.2026
- Решил: разработка (Борис видит и может оспорить)
- Связано: FR-NOTIF-1, FR-NOTIF-4, ST-M7-09, дизайн M7 раздел 10, дизайн v3 разделы 12.1 и 12.4, ADR-001, ADR-016, угроза T15

## Контекст
С 24.10 Борис не может просто поговорить с Сарой в Telegram: бот понимает
только ответы на свои карточки и вопросы, на всё остальное отвечает «не
поняла». В v1 он писал ей что угодно («что по заявкам», «почему не
откликнулась», «поставь на паузу»), и она отвечала от первого лица, помнила
ход разговора, смотрела базу и делала действия.

Дизайн M7 (раздел 10) задумал Секретаря как роль sonnet без инструментов:
код собирает снимок, модель отвечает по схеме одной командой из списка.
28.10 Борис попросил другое: свободный разговор, как с полноценным Claude,
на Opus с усилием medium, с памятью разговора, чтением данных и действиями.
Дизайн v3 (12.1, 12.4) это допускает: у Секретаря есть внутренние
инструменты Сары, задания он получает только от Бориса, а деньги требуют
нажатия Бориса.

Силы: подписка Claude общая с живой Сарой и сессиями разработки; токен
бота читает только ядро (второй читатель ломает getUpdates); данные
клиентов модель видит только метками (ADR-016); роли Сары не получают
файлы и команды (T15); модель предлагает, код решает.

## Решение
Свободные слова Бориса ядро передаёт роли `secretary`: один запуск
`claude -p` на ход разговора (`--model opus --effort medium`), через тот
же шлюз, что все роли (очередь, лимит, журнал `model_call`).

1. **Инструменты только ядра.** Встроенные инструменты CLI выключены
   (`--tools ""`): ни файлов, ни команд, ни веба. Модель видит один
   MCP-сервер `sara` по адресу ядра `/internal/secretary/mcp`, только с
   127.0.0.1 и только с ключом хода, который живёт, пока идёт этот ход.
   Инструменты читают те же представления, что пульт (`pult/*`), и
   действуют теми же функциями, что кнопки (`onPress`, `setSetting` с
   правилом пульта `pultMay`, команды разговора M4).
2. **Деньги и клиент только нажатием.** Инструмент отклика не платит, а
   присылает Борису кнопку «Откликнуться за N ₽» той же задачи; слова
   клиенту Сара показывает с кнопкой «Отправить» (как «напиши: …» в M4).
   Включать траты и письма клиентам Секретарь не может: правило пульта
   разрешает только выключить.
3. **Память разговора в базе, а не в сессии CLI.** Сообщения Бориса и
   ответы Сары лежат в `core.secretary_message` (неделя), в каждый ход
   уходят последние 20 за трое суток. Сессия CLI (`--resume`) не
   используется: её файлы пропали бы при каждой выкладке (контейнер
   пересобирается), метки данных клиентов в ней разошлись бы между ходами,
   а контекст рос бы без предела и тратил подписку.
4. **Данные клиентов метками.** Вход хода и каждый ответ инструмента
   проходят одно общее скрытие хода (имена клиентов, телефоны, почта,
   ссылки); код возвращает значения в ответ Борису и в аргументы действий.
5. **Защита подписки.** Ход только один за раз (сообщения, пришедшие во
   время хода, идут следующим ходом вместе); не больше
   `secretary.turns_per_day` ходов в сутки (по умолчанию 60, меняется в
   пульте); ход длится не дольше 4 минут и не дороже `--max-budget-usd`;
   при лимите Opus ход не запускается, Борис сразу получает «Лимит Claude
   до HH:MM, кнопки и пульт работают».
6. **Порядок разбора сообщения.** Ответ на сообщение бота идёт его
   обработчику, как раньше. Без ответа при открытом вопросе Сары за 30
   минут: слова, похожие на просьбу (начинаются с повелительного слова:
   «откликнись», «покажи», «поставь»…; после «почему?» ещё и с
   вопросительного слова или кончаются «?»), идут Секретарю вместе с этим
   вопросом, и он сам решает, ответ это или просьба (если не ясно,
   спрашивает); остальное ответ на вопрос, как раньше. Пока ждётся новый
   текст отклика, вопрос в конце не в счёт: отклик часто спрашивает
   клиента. Всё прочее идёт Секретарю.

## Рассмотренные варианты
- Роль по схеме без инструментов (дизайн M7, раздел 10): дешевле, но это
  не свободный разговор: одна команда на сообщение, без вопросов к данным
  по ходу мысли. Борис попросил полноценного Claude.
- Отдельная сессия Claude Code с плагином Telegram, как в v1: второй
  читатель токена бота (конфликт getUpdates), полный доступ к файлам и
  командам (T15), обход журнала и лимита шлюза.
- `--resume` одной длинной сессии: см. пункт 3 решения.
- MCP-сервер отдельным процессом (stdio): лишний переход; сервер внутри
  ядра зовёт те же функции напрямую.

## Последствия
- Борис снова говорит с Сарой словами; кнопки, пульт и порядок ответов на
  карточки не меняются.
- Opus в разговоре тратит общую подписку: предел ходов в сутки виден и
  меняется в пульте, каждый ход в `model_call` с ролью `secretary`.
- Инструменты Секретаря добавляются только в `apps/core/src/secretary/tools.ts`;
  новый инструмент, который тратит деньги или пишет клиенту, обязан идти
  через кнопку Бориса (тест на список инструментов).
- Команда `/status` без модели и кнопка `web_app` «Открыть» из дизайна M7
  остаются задачами M7.

## Дополнение 07.11.2026: роль `pinger` читает веб

Борис, 07.11: пинг замолчавшему клиенту может нести свежий факт его рынка
или новость ниши, веб поиск для этого можно, но ни одного факта без ссылки
на источник (дизайн `docs/superpowers/specs/2026-11-07-organic-pings.md`).

Решение. Все роли по-прежнему запускаются с `--tools ""`, кроме тех, что
сами называют встроенные инструменты в `meta.json` (поле `tools`). Список
разрешённых закрыт в контракте: только `WebSearch` и `WebFetch`, файлов и
команд нет ни у одной роли. Сейчас их называет одна роль `pinger`; тест
шлюза держит этот список.

1. **Только эти инструменты и только по имени.** Роль с `tools` получает
   `--tools WebSearch,WebFetch --allowedTools WebSearch WebFetch`, режим
   `dontAsk` остаётся: всё прочее запрещено без вопроса. Прогон ограничен
   `--max-budget-usd` из `meta.json` (у пингера 1) и тайм аутом 4 минуты.
2. **Источник проверяет код, а не модель.** Такая роль отвечает потоком
   событий (`--output-format stream-json --verbose`). Шлюз берёт ответ из
   последнего события `result` и собирает все ссылки, которые вернули
   инструменты (результаты поиска, открытые страницы). Факт пинга идёт с
   полем `source_url`; если его страницы нет среди полученных в этом
   прогоне, проверка `hook.unsourced` (S1) отбрасывает текст, и пинг
   пишется заново без новостей. Слова факта или статистики без такого
   источника тоже `hook.unsourced`.
3. **Данные клиентов метками, как везде.** Вход идёт через то же скрытие
   (ADR-016): имён, телефонов, почты и ссылок клиента в поисковых запросах
   нет. Страницы из веба это данные, не инструкции; результат роли только
   черновик пинга, который уходит клиенту по нажатию Бориса (или по его
   настройке `conv.pings_auto`, по умолчанию выключена).
4. **Подписка.** Пингер на `sonnet` с приоритетом P2 и не больше
   `conv.pings_per_day` вызовов за сутки (по умолчанию 20), сверх этого
   пинг ждёт утра.

Последствия. Новая роль с `tools` проходит ревью как это дополнение: тест
шлюза перечисляет все роли с инструментами. Угроза T15 (роль получает
файлы и команды) не меняется: веб только на чтение. Новая угроза, текст из
веба как инструкция, закрыта тем, что роль ничего не делает сама, кроме
ответа по схеме, а код проверяет и ответ, и источник.
