# ADR-021. Один сервер за рубежом, как у v1

- Статус: принято
- Дата: 22.10.2026
- Решил: Борис («Сервер у нас будет как раньше, не в России»)
- Заменяет: ADR-004; меняет ADR-019

## Контекст
ADR-004 разносил систему на два узла: ядро за рубежом (Claude из России
недоступен) и узел Профи.ру в России (площадка режет зарубежные IP, а
закон требует первой записи данных в России). Борис решил обойтись без
сервера в России. Старая Сара 42 дня работает с сервера в Болгарии;
защита Профи.ру за это время не пускала её один раз, на 48 минут
(08.10.2026).

## Решение
Вся новая Сара живёт на одном сервере за рубежом, отдельном от сервера
v1 (v1 работает до переключения на M7). На нём в Docker Compose: ядро,
бот, пульт, Postgres, разум, бэкап и служба Профи-MCP с браузерами
аккаунтов. Граница площадки остаётся прежней (ADR-003): ядро говорит со
службой Профи-MCP только по контракту C2, по внутренней сети Docker.
Изоляция аккаунта это свой профиль браузера и свой IPv4 на этом сервере
(дополнительный адрес у провайдера). Связи WireGuard нет.

Очередь событий службы Профи-MCP (ADR-019) живёт в отдельной схеме
`node` той же базы: служба записывает событие у себя и доставляет его
ядру с подтверждением.

## Рассмотренные варианты
- Два узла (ADR-004): надёжнее против блокировок площадки и закрывает
  закон, но Борис против сервера в России.
- Сервер в России с доступом к Claude через прокси: нарушает условия
  доступности Claude.

## Последствия
- Дешевле и проще: один сервер на 2-4 ядра и 4-8 ГБ, ориентир
  1000-2500 ₽ в месяц плюс 150-250 ₽ за IP на аккаунт; точнее после
  выбора тарифа.
- Риск блокировки зарубежного IP площадкой остаётся. Меры: бережный
  режим, повтор с паузой и одно 🌐 Борису (как в v1), свой IP на
  аккаунт. Запасной путь, если блокировки станут частыми: выход браузера
  аккаунта через российский прокси без хранения данных (решает Борис).
- Где хранятся данные клиентов: ADR-022.
- Сервер нужен с начала M1 (калибровка на живой сессии).
