    Сара Hance: спецификация

    Один ИИ-сотрудник продаж на Профи.ру. Приносит заявку меньше чем за 2 минуты, после «да» откликается за минуту, разговаривает голосом Бориса, договаривается о встрече, учится на тренажёре. Документ устроен как инженерная спецификация: требования с номерами, архитектура по модели C4, решения, вехи с критериями приёмки.

    Статусна утверждение
    ВладелецБорис Мноян
    Требованийоколо 90 с номерами
    Решений13 ADR
    ВехM0-M8

    Ключевые решения

    ADR-001 БорисClaude через CLI по подпискебез оплаты токенов
    ADR-002, 003Профи.ру гибридно через Профи-MCPсобытия читать, интерфейсом действовать, экраном проверять
    ADR-004 предложениеДва сервераядро за рубежом, узел в России, свой IP на аккаунт
    ADR-005 предложениеПервичная запись в Россиирабочая копия у ядра, уведомление в Роскомнадзор
    ADR-007, 008Разум в git, без дообучениязнание, понимание, речь, суждение, память
    ADR-009 БорисНаправления и маршрутизатораккаунты разного характера без конкуренции
    ADR-010 предложениеНовый ботv1 работает на старом до переключения
    ADR-012 БорисБез календарявстречу отмечает Борис
    Как комментировать. Включи режим комментариев в просмотрщике и нажми на любой блок: комментарий привяжется к нему. Удобно ссылаться на номер требования, например FR-LEAD-7.
    Раздел 2

    Цели, метрики, границы

    Каждая цель измерима и проверяется по журналу событий, а не на ощущениях.

    №ЦельМетрикаЗначение
    G1Быть среди первых откликовот появления заявки до карточки у Борисаменьше 2 минут у 90%
    G2Решение исполняется сразуот «да» до отклика в чатеменьше 60 секунд
    G3Доводить до встречи«клиент ответил → встреча»от 25%
    G4Говорить как Борисслепой тест: Борис отличает свой ответоколо 50%, как угадывание
    G5Снимать работу с Борисадоля ответов без его участия60% через два месяца после M5
    G6Знать деньгицена ответа, встречи, договоракаждый день по направлениям
    G7Не ошибатьсядубли, выдуманные факты, потери данных0

    Не цели первой версии

    • Лора, Ultimate Hance, календарь, ссылки на видеовстречи.
    • Звонки голосом, другие площадки, продажа коробки.
    • Дообучение весов модели.

    Анти-цели: провал, даже если работает

    • Выдуманные факты, траты без решения Бориса.
    • Поток уведомлений, роботный тон.
    • Два аккаунта на одном заказе, дубль, ответ поверх ответа Бориса.
    • Потеря памяти после перезапуска.
    №Сценарий: «Когда…, хочу…, чтобы…»
    JS-1Когда появилась подходящая заявка, хочу готовый отклик с кнопкой, чтобы откликнуться среди первых
    JS-2Когда клиент ответил, хочу, чтобы Сара продолжила моим голосом и звала меня только по моим темам
    JS-3Когда клиент согласился на созвон, хочу время и бриф, чтобы подготовиться
    JS-4Когда Сара ответила не так, хочу поправить один раз, чтобы она запомнила
    JS-5Когда есть 5 минут, хочу потренировать Сару на типовых клиентах
    JS-6Когда завожу аккаунт, хочу описать направление словами и получить надёжную систему оценки
    JS-7Когда что-то сломалось, хочу одно понятное сообщение и кнопку
    JS-8Когда открываю пульт, хочу за 10 секунд понять, что ждёт меня и сколько это приносит
    JS-9Когда ставлю систему с нуля, хочу шаги с инструкцией и проверкой
    Раздел 4

    Функциональные требования

    У каждого требования номер и критерий приёмки. На номера ссылаются планы, тесты и приёмка вех.

    Первый запуск FR-SET

    №ТребованиеПриёмка
    FR-SET-1Мастер из 9 шагов с прогрессом, возвратом, пропуском необязательныхпрерванный мастер продолжается с того же шага
    FR-SET-2Telegram: бот по пошаговой инструкции или токен существующего, привязка чата по /startпонятная ошибка при неверном токене; приходит «Сара на связи»
    FR-SET-3Claude: токен setup-token, проверка входа, пробный вызов, лимитпробный вызов меньше 30 секунд
    FR-SET-4Аккаунт Профи.ру через живой экран браузерасессия жива, баланс виден, присутствие включено
    FR-SET-5«Состояние системы» повторяет все проверкиу каждой проверки итог и что сделать

    Аккаунты и направления FR-ACC

    №ТребованиеПриёмка
    FR-ACC-1Несколько аккаунтов: свой профиль браузера, IP, лимиты, бюджет, паузаданные и IP не смешиваются
    FR-ACC-2Направление: описание, стоп-факторы, система оценки с версиями, формат отклика, кейсы, скоростьу системы оценки есть история
    FR-ACC-3Онбординг: Claude структурирует слова Бориса и спрашивает «Правильно понимаю?»черновик сохраняется на каждом шаге
    FR-ACC-4Калибровка на 20 реальных заявках с предложениями поправоквключение при согласии от 85%
    FR-ACC-5Пересчёт системы оценки на последних N заявкахвидно, у каких заявок изменилось решение
    FR-ACC-6Повторный вход живым экраном с телефонабез Мака и команд

    Заявки и отклики FR-LEAD

    №ТребованиеПриёмка

    FR-LEAD-5Проверка заказа до откликазакрытые не предлагаются
    FR-LEAD-6Черновик в формате направления: приветствие, кейсы по тегам, до 500 знаковприветствие в 100% откликов

    Раздел 6.2C4, уровень 1

    Сара и мир вокруг неё

    Модель C4 описывает систему уровнями, от общего к частному. Первый уровень: кто пользуется системой и с какими внешними системами она говорит.

    Раздел 6.3, 6.5C4, уровень 2

    Из чего состоит Сара и где это работает

    Два сервера. Ядро за рубежом, где официально доступен Claude. Узел Профи.ру в России: его видит площадка, и на нём первая запись данных клиентов.

    IP на аккаунтна узле Профи.ру1 IPv4150-250 ₽
    Бэкапыдругой провайдер, S3100-300 ₽
    Итогооколо 2000-3500 ₽ в месяц плюс подписка Claude
    Раздел 6.4C4, уровень 3

    Что внутри ядра

    Ядро разбито на компоненты с границами: событие входит, разум понимает, правила решают, исполнение делает. Всё пишется в журнал.

    Раздел 8предложение

    Где хранить данные

    Закон о персональных данных (ст. 18 ч. 5): данные граждан России при сборе сначала записываются в базу в России, копию потом можно передать за рубеж с уведомлением Роскомнадзора. Штраф для юрлица и ИП 1-6 млн ₽. Claude для работы нужен текст в момент вызова, а не место хранения, поэтому одно другому не мешает.

    Правила хранения предложение

    • Переписка закрытых клиентов хранится 2 года, затем удаляется.
    • В разум и тренажёр попадают только обезличенные тексты.
    • Удаление по просьбе клиента одной командой из пульта.
    • Уведомления в Роскомнадзор об обработке и о трансграничной передаче подаются один раз до запуска.

    Режимы деградации

    • Нет Claude: готовые тексты для срочного, черновики позже, одно сообщение.
    • Нет площадки: ожидание и одно сообщение, без перегрузки сайта.
    • Нет Telegram: очередь уведомлений, пульт работает.
    • Нет связи узлов: очередь команд и досылка событий.
    • Разлогин или блокировка: стоит только этот аккаунт.

    Наблюдение

    • Трасса хода: событие, отобранный разум, вызов модели, проверки, правило, итог.
    • Метрики: время до карточки, до отклика, до ответа; доля без Бориса; лимит; ошибки по классам.
    • Тревоги Борису: только то, что требует его действия.
    • Тревоги разработке: GlitchTip, очереди, свежесть бэкапа, последнее событие площадки.

    Как идёт разработка

    GitHub-аккаунт Бориса уже подключён на этом Маке (perpetumxcompany-alt). Код и разум живут в двух приватных репозиториях, каждое изменение проходит один и тот же путь.

    Правила

    • main защищена: только пул-реквест с зелёным CI.
    • CI GitHub Actions: тесты, типы, сборка образов в GitHub Container Registry.
    • Выкладка: сервер сам забирает нужную версию; откат одной командой.
    • Окружения: Мак с фальшивым Профи.ру, тень на серверах, работа.
    • Секреты: зашифрованы, никогда открыто в репозитории.
    • Задачи: GitHub Project с вехами, задача плана это issue.
    • Решения: ADR в docs/adr, документ передачи дел после каждого блока.
