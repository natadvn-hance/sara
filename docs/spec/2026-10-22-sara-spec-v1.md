## 0. Сводка на одну страницу

**Проблема.** Сара v1 за 42 дня: 4369 заявок, 26 откликов на 3277 ₽, 70%
клиентов ответили, 0 встреч, 0 известных договоров. Память теряется, итоги
не считаются, эксплуатация ручная, 41 находка аудита.

**Решение.** Новая Сара: один ИИ-сотрудник продаж на Профи.ру с разумом
по идее Бориса (знание, понимание, речь, суждение, память). Видит заявку и
приносит её Борису меньше чем за 2 минуты, после «да» откликается за
минуту, разговаривает голосом Бориса, договаривается о встрече, учится на
тренажёре и правках. Несколько аккаунтов разных направлений без
конкуренции. Один пульт: веб-приложение, Mini App, бот.

**Ключевые решения:**
1. Модель через Claude Code CLI по подписке, без API **[Б]** (ADR-001).
2. Профи.ру гибридно: события и данные сайта для чтения, интерфейс для
   действий, проверка экраном; всё за границей Профи-MCP (ADR-002, 003).
3. Один сервер за рубежом, как у v1: ядро и служба Профи-MCP вместе, по
   отдельному IP на аккаунт (ADR-021) **[Б]**.
4. Данные клиентов на этом сервере, обезличивание перед вызовом модели,
   сроки хранения; риск по 152-ФЗ принят Борисом, юрист до M1 (ADR-022,
   ADR-016) **[Б]**.
5. Разум как git-репозиторий файлов, обучение без дообучения модели
   (ADR-007, 008).
6. Направления аккаунтов с системой оценки от Claude и маршрутизатор
   (ADR-009) **[Б]**.
7. Новый бот Telegram (ADR-010) **[Б]**.
8. Без календаря, встречу отмечает Борис (ADR-012) **[Б]**.

**Метрики успеха:** заявка у Бориса меньше чем за 2 минуты; отклик меньше
чем за минуту после «да»; «ответил → созвон» от 25%; 60% ответов без
Бориса через два месяца; в слепом тесте Борис не отличает себя от Сары; 0
дублей и выдуманных фактов.

**Вехи:** M0 фундамент и сквозной путь → M1 Профи-MCP → M2 заявки и отклик в одно
нажатие → M3 направления → M4 разум и разговор → M5 тренажёр и обучение
→ M6 встречи и итоги → M7 пульт и переключение с v1 → M8 второй
аккаунт.

## 1. Контекст

- **Площадка.** Профи.ру: клиенты публикуют заказы, специалисты платят за
  отклик (в маркетинге в среднем 192 ₽). Публичного API для специалистов
  нет.
- **Как площадка распределяет заказы** (справка Профи.ру): место отклика
  задаёт рейтинг анкеты; клиент видит отклики в порядке поступления; если
  заказ подходит многим, его сначала показывают тем, кто чаще
  договаривается. Значит, решают скорость и доля договорённостей.
- **v1** работает на сервере в Болгарии: демон с браузером, сессия Claude
  Code в Telegram, Mini App. Аудит нашёл 41 проблему: 12 критичных, 23
  важных, 6 мелочей.
- **Ресурсы:** подписка Claude, малый бюджет на серверы, разработка
  силами сессий Claude Code, Борис принимает решения и результат.

## 2. Цели, метрики, границы

### 2.1 Цели и как их мерить

| № | Цель | Метрика | Значение | Как мерится |
|---|---|---|---|---|
| G1 | Быть среди первых откликов | время от появления заявки до карточки у Бориса | меньше 2 минут у 90% заявок | журнал событий |
| G2 | Решение Бориса исполняется сразу | время от «да» до отклика в чате | меньше 60 секунд | журнал |
| G3 | Доводить до встречи | доля «клиент ответил → встреча назначена» | от 25% | когорты |
| G4 | Говорить как Борис | слепой тест: Борис отличает свой ответ | не лучше угадывания (около 50%) | тренажёр, раз в неделю |
| G5 | Снимать работу с Бориса | доля ответов клиентам без участия Бориса | 60% через два месяца после M5 | журнал |
| G6 | Знать деньги | цена ответа, встречи, договора по направлениям | считается каждый день | аналитика |
| G7 | Не ошибаться | дубли, выдуманные факты, потери данных | 0 | проверки, аудит журнала |

### 2.2 Не цели первой версии

Лора, Ultimate Hance, календарь, ссылки на видеовстречи, звонки голосом,
другие площадки, продажа коробки, дообучение весов модели.

### 2.3 Анти-цели

Провал, даже если «работает»: выдуманные факты; траты без решения Бориса;
поток уведомлений; два аккаунта на одном заказе; роботный тон; дубль или
ответ поверх ответа Бориса; потеря памяти после перезапуска.

## 3. Пользователи и сценарии

**Борис** (владелец, единственный пользователь пульта): решает про деньги
и клиентов, принимает работу Сары, учит её. Пишет коротко, с телефона и
компьютера. Нужен простой язык и одно сообщение вместо многих.

**Клиент Профи.ру** (внешний): видит только сообщения в чате площадки. Не
должен почувствовать робота.

| № | Сценарий («Когда…, хочу…, чтобы…») |
|---|---|
| JS-1 | Когда на площадке появилась подходящая заявка, хочу получить готовый отклик с кнопкой, чтобы откликнуться среди первых |
| JS-2 | Когда клиент ответил, хочу, чтобы Сара продолжила разговор моим голосом и звала меня только по моим темам |
| JS-3 | Когда клиент согласился на созвон, хочу узнать время и бриф, чтобы подготовиться |
| JS-4 | Когда Сара ответила не так, как я, хочу поправить один раз, чтобы она запомнила |
| JS-5 | Когда есть свободные 5 минут, хочу потренировать Сару на типовых клиентах |
| JS-6 | Когда завожу новый аккаунт, хочу описать направление словами и получить систему оценки, которой можно доверять |
| JS-7 | Когда что-то сломалось, хочу одно понятное сообщение и кнопку, что сделать |
| JS-8 | Когда открываю пульт, хочу за 10 секунд понять, что ждёт меня и сколько это приносит |
| JS-9 | Когда ставлю систему с нуля, хочу пройти шаги с инструкцией и проверкой |

## 4. Функциональные требования

Формат: номер, требование, критерий приёмки.

### 4.1 Первый запуск (FR-SET)

| № | Требование | Критерий приёмки |
|---|---|---|
| FR-SET-1 | Мастер из 9 шагов с прогрессом, возвратом, пропуском необязательных | прерванный мастер продолжается с того же шага |
| FR-SET-2 | Telegram: создание бота по пошаговой инструкции или токен существующего; проверка; привязка чата по /start | неверный токен даёт понятную ошибку и путь исправления; приходит «Сара на связи» |
| FR-SET-3 | Claude: токен `claude setup-token`, проверка входа, пробный вызов, состояние лимита | пробный вызов haiku отвечает меньше чем за 30 секунд |
| FR-SET-4 | Аккаунт Профи.ру через живой экран браузера | сессия жива, виден баланс, включено присутствие |
| FR-SET-5 | Страница «Состояние системы» повторяет все проверки | каждая проверка показывает итог и что сделать |

### 4.2 Аккаунты и направления (FR-ACC)

| № | Требование | Критерий приёмки |
|---|---|---|
| FR-ACC-1 | Несколько аккаунтов; у каждого свой профиль браузера, IP, лимиты, бюджет, пауза | два аккаунта работают одновременно, данные и IP не смешиваются |
| FR-ACC-2 | Направление на аккаунт: описание, стоп-факторы, система оценки с версиями, формат отклика, кейсы, режим скорости | всё редактируется в «Аккаунтах», у системы оценки есть история |
| FR-ACC-3 | Онбординг направления: на каждом шаге Claude структурирует слова Бориса и спрашивает «Правильно понимаю?» | 8 шагов из дизайна, черновик сохраняется на каждом |
| FR-ACC-4 | Калибровка на 20 реальных заявках: отметки Бориса, расхождения, предложения поправок | направление включается при согласии от 85% |
| FR-ACC-5 | Пересчёт системы оценки на последних N заявках | показаны заявки, у которых изменилось решение |
| FR-ACC-6 | Повторный вход живым экраном, в том числе с телефона | вход без Мака и без команд |

### 4.3 Заявки и отклики (FR-LEAD)

| № | Требование | Критерий приёмки |
|---|---|---|
| FR-LEAD-1 | Новая заявка замечается по событиям площадки, обновлению ленты раз в минуту и письмам | меньше 60 секунд у 90% заявок |
| FR-LEAD-2 | Первый отбор правилами кода и Сортировщиком | явно чужие отсеяны без вызова сильной модели |
| FR-LEAD-3 | Оценка системой каждого направления: балл, обоснование, уверенность, обязательные условия | у каждой оценки видно «почему N» |
| FR-LEAD-4 | Маршрутизатор: заявка достаётся одному направлению; если подходят оба, одна карточка с выбором | два отклика на один заказ невозможны (проверка в коде и в тесте) |
| FR-LEAD-5 | Проверка заказа до отклика: открыт ли, место, цена | закрытые заказы не предлагаются |
| FR-LEAD-6 | Черновик отклика в формате направления: приветствие, кейсы по тегам, до 500 знаков | приветствие в 100% откликов |
| FR-LEAD-7 | Карточка Борису в Telegram и пульте: заявка целиком, клиент, балл, разбор, черновик, ссылка на заявку; кнопки Откликнуться за N ₽, Разбор, Изменить, Пропустить с причиной. Карточка заявки приходит один раз, повторов нет (Борис, 26.10.2026); карточку, которая не дошла, Сара доставляет один раз через reminder.decision_after_min | меньше 2 минут от появления заявки |
| FR-LEAD-8 | Отклик после «да» через интерфейс с проверкой экраном | меньше 60 секунд; отклик найден на странице; трата записана на заказ |
| FR-LEAD-9 | Деньги: кошелёк, способ оплаты, лимиты дня, потолок за отклик; автоотклик только по правилу направления, по умолчанию выключен | ни одной траты без «да» или включённого правила |
| FR-LEAD-10 | Очередь по ценности; заявки старше 24 часов не предлагаются | заявка старше 24 часов не попадает в карточку и очередь; очередь отсортирована по баллу и цене (тест) |

### 4.4 Разговор с клиентом (FR-CONV)

| № | Требование | Критерий приёмки |
|---|---|---|
| FR-CONV-1 | Новое сообщение замечается по событию, страховка сверкой раз в 10 минут | меньше 60 секунд у 95% сообщений |
| FR-CONV-2 | Сообщения хранятся с номером площадки, автором, временем, отметкой «прочитано» | автор определён у 100% сообщений, иначе действий нет |
| FR-CONV-3 | Цикл ответа из 8 шагов; ответ содержит номера фактов из разума | у каждого ответа Сары в журнале трасса 8 шагов и номера фактов; ответ без номеров фактов не отправляется |
| FR-CONV-4 | Проверка: факты, приветствие на новом дне, роботность, длинное тире; провал даёт черновик | 0 отправленных ответов с фактом вне разума |
| FR-CONV-5 | Правила: пауза, тихие часы, владелец клиента, самостоятельность по теме | на паузе, в тихие часы, у клиента Бориса и на теме «черновик» ответ клиенту не уходит (тест на каждое правило) |
| FR-CONV-6 | Перед отправкой чат перечитывается; если клиент дописал или Борис ответил, цикл заново | 0 ответов поверх ответа Бориса |
| FR-CONV-7 | Пока клиент печатает, Сара ждёт; несколько сообщений получают один ответ | три сообщения клиента подряд с «печатает» между ними получают один ответ (тест E9) |
| FR-CONV-8 | Человеческая пауза 1-4 минуты, набор в интерфейсе; ночью только срочное | пауза перед отправкой от 1 до 4 минут у 100% ответов; с 23:00 до 8:00 уходит только срочное |
| FR-CONV-9 | Отправка с ключом от повтора; своё сообщение найдено на странице | 0 дублей |
| FR-CONV-10 | Борис написал сам в Профи.ру: клиент Бориса, черновик отменён | после сообщения Бориса в чате владелец клиента `boris`, черновик отменён (тест E8) |
| FR-CONV-11 | Команды Бориса: беру сам, вернуть Саре с указанием, написать текст, закрыть | из пульта, бота и Mini App |
| FR-CONV-12 | Напоминания клиенту по лестнице с учётом «прочитал или нет»; застой 7 дней | напоминание не уходит, если клиент ответил; после 7 дней без ответа клиент в застое и задача Борису |

### 4.5 Речь (FR-SPEECH)

| № | Требование | Критерий приёмки |
|---|---|---|
| FR-SPEECH-1 | Портрет речи Бориса: форма, словарь, прагматика, темп; строится учителем, подтверждается Борисом | видна в «Разуме», каждая черта с источниками |
| FR-SPEECH-2 | На каждый ход 3-5 образцов Бориса, подобранных по теме и тону | в трассе хода 3-5 образцов с источником; образцы только с автором `boris` |
| FR-SPEECH-3 | Тон клиента определяется на каждом ходе: шутка, раздражение, спешка, сомнение, комплимент, грубость, торг | тон записан в трассе каждого хода; на золотом наборе совпадение с оценкой Бориса от 80% |
| FR-SPEECH-4 | Слепой тест раз в неделю: 5 пар «Борис или Сара» | результат в «Экзаменах» |

### 4.6 Встречи (FR-MEET)

| № | Требование | Критерий приёмки |
|---|---|---|
| FR-MEET-1 | Свободное время Бориса в настройках: дни, часы, длительность, максимум в день, исключения | Сара не предлагает время вне свободного времени и сверх максимума в день (тест) |
| FR-MEET-2 | Процедура созвона: способ связи, 2-3 времени в разные дни, выбор клиента свободной фразой, перенос | без пересечений со встречами Сары |
| FR-MEET-3 | Telegram «встреча назначена» с брифом, напоминания утром и за 30 минут | «встреча назначена» приходит меньше чем через минуту после согласия клиента; каждое напоминание ровно один раз |
| FR-MEET-4 | После встречи «Прошла ли встреча?» с итогами; договор с суммой | итог попадает в аналитику |

### 4.7 Разум (FR-MIND)

| № | Требование | Критерий приёмки |
|---|---|---|
| FR-MIND-1 | Разум в git-репозитории файлов: пять частей, общее для Hance и своё для направления | каждый ответ хранит версию разума |
| FR-MIND-2 | Поиск: полнотекстовый по-русски и локальные векторы | ответ поиска меньше 300 мс |
| FR-MIND-3 | Изменения только после «да» Бориса; откат версии одной кнопкой | без «да» запись остаётся в `proposals/` и не попадает в индекс; откат возвращает прошлую версию одним нажатием |
| FR-MIND-4 | Интервью карточками для пробелов знания | после ответа Бориса на карточку появляется запись разума со ссылкой на интервью |

### 4.8 Обучение и тренажёр (FR-TRAIN)

| № | Требование | Критерий приёмки |
|---|---|---|
| FR-TRAIN-1 | Выгрузка всей истории чатов Профи.ру всех аккаунтов с разделением авторов: клиент, Борис, Сара v1 | сообщения Сары v1 не считаются голосом Бориса |
| FR-TRAIN-2 | Сценарии и персоны тренажёра строятся из истории Профи.ру, обезличенно **[Б]** | источник у каждой персоны |
| FR-TRAIN-3 | Тренажёр в пульте: пять режимов (клиент пишет и отвечаешь ты; угадай Бориса; Сара отвечает и ты оцениваешь; трудные случаи; интервью) | тренировка не уходит клиентам |
| FR-TRAIN-4 | Панель Сары: её вариант, разница, «Запомнить», обсуждение | у каждой реплики Бориса вариант Сары и разница; «Запомнить» создаёт карточку урока |
| FR-TRAIN-5 | Итог тренировки и карта покрытия типов вопросов | после тренировки видно, что выучено и какие типы вопросов покрыты |
| FR-TRAIN-6 | Уроки из правок в работе, карточки пачками по 5 | правка Бориса создаёт урок; уроки приходят пачками по 5 |
| FR-TRAIN-7 | Ночной учитель: черновики разума | ничего не меняется без «да» |

## 6. Архитектура

### 6.1 Принципы

1. Одна Сара: один разум и одна память на все входы.
2. Один источник правды: журнал событий.
3. Модель предлагает, код решает: деньги, отправку, паузы проверяет код.
4. У аккаунта один владелец браузера: Профи-MCP.
5. Действия наружу через исходящую очередь с подтверждением.
6. Долгие процессы переживают перезапуск.
7. Неуверенность останавливает действие.
8. Всё измеряется.

### 6.2 Уровень 1: контекст (C4)

Сара связана с пятью внешними системами: Профи.ру (заказы и чаты),
Telegram (бот и Mini App), Claude (через CLI по подписке), почта Профи.ру
(резервный сигнал), хранилище бэкапов. Пользователь один: Борис. Клиенты
Профи.ру общаются с Сарой только через чат площадки.

### 6.3 Уровень 2: контейнеры

| Контейнер | Где | Ответственность | Технология |
|---|---|---|---|
| Ядро (core) | сервер | домен, машина состояний, движок правил, устойчивые процессы, шлюз модели, мозг, школа, аналитика, API | TypeScript, Node 24, Fastify, DBOS |
| Бот | сервер | Telegram: уведомления, кнопки, разговор с Сарой | grammY |
| Пульт | сервер | веб-приложение и Mini App | React, Vite |
| База | сервер | схема `core`: журнал, данные, индекс разума; схема `node`: сырые данные площадки и очередь событий Профи-MCP | Postgres 16, pgvector |
| Разум | сервер | файлы знаний с версиями | git-репозиторий `sara-mind` |
| Claude CLI | сервер | вызовы ролей по подписке | Claude Code CLI, закреплённая версия |
| Профи-MCP | сервер, отдельная служба | граница площадки: живые вкладки, события, чтение, действия, живой вход | TypeScript, Playwright, MCP SDK |

### 7.2 Машина состояний клиента

Этапы: `found → queued → bid_sent → talking → call_proposed →
call_booked → call_done → won | lost`, плюс `dormant`. Владелец: `sara`,
`boris`, `paused`. Чей ход: `client`, `sara`, `boris`, `nobody`.
Эскалация меняет владельца, чат читается всегда. Каждый этап запускает
свои устойчивые процессы (напоминания, ожидания) и отменяет процессы
прошлого этапа.

### 7.3 Цикл ответа

Шаги: услышать → вспомнить → понять (смысл и тон) → сказать → проверить
→ правила → отправить → научиться. Таблица шагов, исполнителей и
поведения при сбое: дизайн v3, раздел 6.

### 7.4 Шлюз модели и роли

**Контракт вызова роли:**

```
claude -p --model <haiku|sonnet|opus> --fallback-model <запасная>
  --system-prompt-file roles/<роль>.md
  --append-system-prompt-file <контекст>.md
  --output-format json --json-schema <схема роли>.json
  --tools "" --strict-mcp-config
  --setting-sources project --permission-mode dontAsk --permission-prompts none
  --max-turns <N> --no-session-persistence
```

- Роли (11): Сортировщик, Оценщик и маршрутизатор, Аналитик, Собеседник,
  Проверяющий, Секретарь, Тренер, Онбординг направления, Учитель,
  Экзаменатор и генератор, Ремонтник вёрстки. Модели и инструменты: дизайн
  v3, раздел 12.1.
- Приоритеты: P0 клиенты, Борис, быстрые заявки; P1 отклики, тренажёр; P2
  лента; P3 учёба ночью.
- Параллельно 2 вызова; счётчик лимита в окнах 5 часов и недели; пауза
  при окончании лимита до времени сброса.
- Отказ от вызова без `structured_output` считается сбоем.
- Слой `gateway` спрятан за интерфейсом: при смене правил Anthropic можно
  переключиться на API без изменений в остальном коде (ADR-001).

### 7.5 Профи-MCP

**Инструменты** (`profi.*`): `session_health`, `list_feed`, `get_order`,
`list_chats`, `read_chat`, `submit_bid`, `send_message`, `backfill_chats`.
Изменяющие инструменты принимают ключ от повтора и разрешение ядра.

**События** (Профи-MCP → ядро): `order_seen`, `order_changed`,
`client_message`, `client_typing`, `client_read`, `chat_closed`,
`session_dead`, `profile_banned`, `layout_changed`, `balance_changed`.

**Движок:** живая вкладка на аккаунт; глаза 1: события `window.__RTP`;
глаза 2: данные из ответов сайта; глаза 3: разметка; руки: клики и набор
текста, очередь команд, бережный режим, проверка экраном после действия.

**Калибровка (первое, что делается в M1):** служба Профи-MCP на своей сессии
записывает события и ответы сайта при обычной работе; из записей
собираются схемы и тестовые образцы. Второй браузер с той же сессией
запрещён.

### 7.6 Разум

Репозиторий `sara-mind`:

```
mind/
  shared/                 # общее для Hance
    knowledge/*.md        # факты, услуги, цены, кейсы
    understanding/*.md    # типы вопросов
    speech/portrait.md    # портрет речи
    speech/examples/*.md  # образцы Бориса (обезличенные)
    judgment/*.md         # конституция, процедуры этапов
  directions/<id>/        # то же для направления
  proposals/              # черновики учителя, до «да» Бориса
```

Каждая запись: поля сверху (тип, статус, версия, источники, область,
действует с, до) и текст. Подтверждение Бориса это коммит. Индекс
обновляется после коммита.

### 7.7 Обучение

Источники: работа (правки), тренажёр, история Профи.ру. Всё проходит
через карточки «Запомнить?», затем в разум. Учитель ночью, экзамен перед
выкладкой, генератор для поиска дыр. Подробно: дизайн v3, раздел 8.

### 7.8 Направления и маршрутизатор

Система оценки: обязательные условия (проходит или нет), критерии с
весами, балл 0-100, обоснование, уверенность. Маршрутизатор выбирает
направление с выполненными условиями и лучшим баллом; два подходящих дают
одну карточку с выбором. Калибровка: 20 заявок, согласие от 85%.

### 7.9 Движок правил

| Правило | Где применяется |
|---|---|
| Пауза «Пишет клиентам» | любая отправка клиенту |
| Пауза «Тратит деньги» и пауза аккаунта | отклики |
| Деньги: кошелёк, лимиты, потолок, «да» или правило направления | отклики |
| Владелец клиента | ответы клиенту |
| Самостоятельность по теме | ответы клиенту |
| Тихие часы | напоминания, ответы не по срочному |
| Бережный режим аккаунта | любые действия на площадке |
| Сессия жива, профиль не заблокирован | любые действия на площадке |

### 7.10 Исходящая очередь

Запись намерения с ключом от повтора → выполнение через Профи-MCP →
проверка экраном → отметка. При сбое связи повтор только после проверки,
что действие не выполнено.

### 7.11 Уведомления

Шесть видов: заявка, черновик, клиент написал (если клиент у Бориса),
встреча, срочно, сводки. Кнопки передают номер задачи; ответ Бориса на
уведомление привязан к нему. Ночью без звука.

### 7.12 Пульт

Информационная архитектура по OOUX: вещи (Аккаунт, Направление, Заявка,
Клиент, Сообщение, Встреча, Задача, Знание, Урок, Тренировка, Экзамен),
связи с числом, действия, атрибуты: дизайн v3, раздел 16. API пульта:
ресурсы по вещам, живые обновления через SSE, вход по паролю и через
подпись Telegram.

### 7.13 Мастер запуска

9 шагов: дизайн v3, раздел 19; требования FR-SET.

### 8.2 Где хранить **[Б]**

Закон о персональных данных (ст. 18 ч. 5): данные граждан России при
сборе сначала записываются в базу в России; потом копию можно передать за
рубеж по правилам ст. 12 с уведомлением Роскомнадзора. Штраф за нарушение
для юрлица и ИП 1-6 млн ₽, повторно 6-18 млн ₽.

~~Решение v1.0: первичная запись на узле в России.~~ **Решение Бориса
22.10.2026 (ADR-022):** сервера в России нет, данные клиентов хранятся
на сервере за рубежом, как у v1. Риск по ст. 18 ч. 5 Борису объяснён и
принят. Меры: минимум данных, сроки хранения, удаление по просьбе
клиента, обезличивание перед моделью, консультация юриста до M1. Сырые
данные площадки лежат в отдельной схеме `node`: если юрист скажет, что
без первой записи в России нельзя, её можно перенести в управляемую базу
в России без своего сервера и без переделки ядра.

**Уточнение v1.1.** Вызов Claude это тоже передача текста за рубеж, в
США, а США не в списке стран с адекватной защитой. Поэтому шлюз
обезличивает данные клиента перед вызовом модели (ADR-016). Вопросы к
юристу (ст. 12, 18 ч. 5, 18.1, 22): модель угроз, раздел 5.

## 13. Процесс разработки

### 13.1 Где живёт код

- GitHub-аккаунт Hance: `natadvn-hance` (решение Бориса 22.10; прежний
  аккаунт `perpetumxcompany-alt` больше не используется), вход на Маке
  выполнен с правами `repo` и `workflow`. Код: https://github.com/natadvn-hance/sara,
  разум: https://github.com/natadvn-hance/sara-mind.
- Два приватных репозитория **[Б]**:
  - `sara`: весь код (ядро, бот, пульт, Профи-MCP), документы,
    инфраструктура, тесты;
  - `sara-mind`: разум Сары; отдельно, потому что меняется каждый день
    после «да» Бориса и откатывается независимо от кода.
- Структура `sara`:

```
apps/core        ядро и бот
apps/web         пульт и Mini App
apps/profi-node  Профи-MCP и браузеры
packages/shared  общие типы и схемы
roles/           инструкции ролей и схемы ответов
infra/           docker compose, конфигурация серверов, бэкапы
docs/            спецификация, ADR, планы, документ передачи дел, справка
tests/           фальшивый Профи.ру, образцы, экзамен
```

### 13.2 Как идёт работа

```
веха → план (задачи с критериями) → ветка на задачу → тесты первыми →
код → пул-реквест → CI (тесты, типы, сборка) → проверка кода →
слияние в main → выкладка в тень → приёмка Борисом → выкладка в работу
```

- **Ветки:** `main` защищена, изменения только через пул-реквест с
  зелёным CI.
- **CI** (GitHub Actions): тесты, проверка типов, сборка образов в GitHub
  Container Registry. Экзамен с моделью запускается на сервере, а не в
  GitHub: токен подписки остаётся на нашем сервере.
- **Выкладка:** сервер сам забирает образ нужной версии и перезапускает
  службы; откат одной командой на прошлую версию.
- **Окружения:** локальное (Мак, фальшивый Профи.ру), тень (серверы,
  живая площадка без отправки), работа.
- **Секреты:** в зашифрованных файлах (sops) и на сервере, никогда в
  открытом виде в репозитории.
- **Задачи:** GitHub Project с вехами M0-M8, каждая задача плана это
  issue.
- **Решения:** каждое архитектурное решение записывается как ADR в
  `docs/adr/`.
- **Документ передачи дел** обновляется после каждого блока работы.

### 13.3 Кто что делает

| Борис | Сара (сессии Claude Code) |
|---|---|
| решения, отмеченные **[Б]** и **[П]** | планы, код, тесты, документы |
| GitHub, серверы, бот, подписка, вход на Профи.ру | настройка серверов по инструкции, выкладка |
| приёмка каждой вехи по критериям | проверка кода, экзамены, отчёт о вехе |
| интервью и тренировки для разума | подготовка тренировок и карточек |

### 13.4 Готово, когда (Definition of Done)

Задача готова, если: требования с её номерами выполнены и проверены
тестом; закрыт чек-лист аспектов (дизайн v3, раздел 22); CI зелёный;
проверка кода пройдена; документы и справка обновлены; изменения
поведения прошли экзамен. Полный текст по уровням (история, веха,
включение в работу) и «Готово к работе»:
`docs/quality/definition-of-ready-and-done.md`.

## 14. Бот, серверы, подписка

- **Бот:** новый **[Б]** (ADR-010), плюс отдельный бот для разработки. Создаётся в мастере запуска за 2
  минуты. v1 продолжает работать на старом боте до переключения: два
  приложения не могут читать одного бота одновременно.
- **Сервер:** один, за рубежом, как у v1 **[Б]** (ADR-021). Для M0 не

- **Подписка:** отдельная подписка для Сары **[Б]**, чтобы её лимит не
  зависел от работы Бориса с Лорой и разработкой. Нужна к M2.

## 17. Риски

| Риск | Вероятность | Ущерб | Мера |
|---|---|---|---|
| Блокировка аккаунта Профи.ру | средняя | высокий | бережный режим, интерфейс, отдельный IP, тревога сразу |
| Смена сайта Профи.ру | высокая | средний | события и данные вместо разметки, образцы, ремонтник |
| Лимит подписки | средний | высокий | шлюз, приоритеты, ночное окно, отдельная подписка |
| Изменение правил Anthropic для `claude -p` | низкая | высокий | шлюз за интерфейсом, переход на API без переделки |
| Голос Сары не похож на Бориса | средняя | средний | тренажёр, образцы, слепой тест |
| Закон о персональных данных: первая запись не в России (ст. 18 ч. 5) | средняя | высокий | риск принят Борисом (ADR-022); минимум данных, сроки, обезличивание, юрист до M1; запасной путь: управляемая база в России для схемы `node` |
| Профи.ру не пускает зарубежный IP | средняя | высокий | бережный режим, повтор с паузой, одно 🌐, свой IP на аккаунт; запасной путь: российский прокси на выход браузера (решает Борис) |
| Контекст разработки теряется между сессиями | средняя | средний | спецификация, ADR, планы, документ передачи дел, тесты |
| Связь аккаунтов друг с другом | средняя | высокий | разные IP, профили, проверка правил у поддержки |
| Нехватка времени Бориса на обучение | средняя | средний | тренировки по 5 минут в Mini App, карточки пачками |
| Две сессии одного аккаунта (v1 и новый сервер) выбивают друг друга | неизвестна | высокий | проверка в первые 48 часов M1; новая Сара только читает по расписанию до M7 |
| Передача данных клиентов в Claude (США) | средняя | высокий | обезличивание перед вызовом (ADR-016), юрист до M1 |
| Обе Сары пишут одному клиенту при переключении | низкая | высокий | флаги по частям, пауза v1 (`docs/ops/migration-and-cutover.md`) |

## 18. Архитектурные решения (ADR)

| № | Решение | Почему | Отвергнуто |
|---|---|---|---|
| ADR-001 | Модель через Claude Code CLI по подписке **[Б]** | без оплаты токенов; официальный инструмент | API по ключу: платно |
| ADR-002 | Профи.ру гибридно: события и данные читать, интерфейсом действовать, экраном проверять | Профи.ру сам решает, кому показывать; нужен вид живого специалиста | только экран: медленно; прямые запросы: риск аккаунта; API приложения: защита и риск |
| ADR-003 | Профи-MCP как единственная граница площадки | один владелец браузера, понятные инструменты, тесты | доступ к браузеру из разных мест: убил сессию 29.09 |
| ~~ADR-004~~ | Два узла (заменено ADR-021) | Claude не работает из России, Профи.ру режет зарубежные IP; изоляция аккаунта это профиль и IP | один сервер: конфликт стран; сервер на аккаунт: дорого без пользы; прокси: дорого и ненадёжно |
| ~~ADR-005~~ | Первичная запись в России (заменено ADR-022) | закон о локализации и удобство работы с Claude одновременно | всё за рубежом: риск штрафа; всё в России: Claude недоступен |
| ADR-006 | Postgres, журнал событий, DBOS | надёжность, история, устойчивые процессы без отдельного сервера | SQLite: одна запись за раз; Temporal: тяжело |
| ADR-007 | Разум как git-репозиторий файлов плюс индекс | версии, откат, нативно для Claude Code | только таблицы: хуже история; отдельный граф: избыточно |
| ADR-008 | Обучение без дообучения модели | дообучать Claude нельзя; разум, образцы, экзамены дают эффект | своя модель: дорого и слабее |
| ADR-009 | Направления и маршрутизатор **[Б]** | аккаунты разного характера без конкуренции | одна оценка на всех: аккаунты мешают друг другу |
| ADR-010 | Новый бот Telegram **[Б]** | v1 работает на старом до переключения; чистое меню и Mini App | тот же бот: конфликт двух приложений |
| ADR-011 | TypeScript-монорепозиторий, React для пульта и Mini App | один язык, общие типы, наработки v1 | разные языки: дороже сопровождать |
| ADR-012 | Без календаря в первой версии **[Б]** | встречу отмечает Борис | Google Calendar: не нужен сейчас |
| ADR-013 | Интерфейс по OOUX | связи между разделами понятны без объяснений | экраны без карты: путаница |
| ADR-014 | Контракты в коде на zod, OpenAPI и JSON Schema генерируются | один источник правды для разных сессий | OpenAPI руками: двойная работа |
| ADR-015 | M0 как ходячий скелет со сквозным путём | главные риски снимаются в первую неделю | фундамент без пути: риски всплывут в M2 |
| ADR-016 | Обезличивание перед вызовом модели | вызов Claude это передача в США | без обезличивания: юридический риск |
| ADR-017 | Два фальшивых Профи.ру и записанные образцы | ни один тест не ходит на живую площадку | тесты на живой площадке: риск аккаунта |
| ADR-018 | Короткие ветки, Conventional Commits, release-please | версии и список изменений сами | ручные выпуски |
| ADR-019 | Служба Профи-MCP доставляет события через свою очередь (схема `node`) | в ядро уходит только нужное | логическая репликация: копирует всё |
| ADR-020 | Drizzle и миграции «расширить, потом сузить» | откат кода без отката базы | ломающие миграции |
| ADR-021 | Один сервер за рубежом, как у v1 **[Б]** | решение Бориса 22.10; проще и дешевле | два узла с российским (ADR-004) |
| ADR-022 | Данные клиентов на сервере за рубежом **[Б]** | решение Бориса 22.10; риск по 152-ФЗ принят | первая запись в России (ADR-005) |

Полный текст каждого решения: `docs/adr/`. ADR-010, 021, 022 приняты
Борисом 22.10.2026 (021 и 022 заменили 004 и 005); ADR-014..020
предложены разработкой и приняты Борисом вместе с пакетом («меня всё
устраивает»).

## 20. Словарь

| Слово | Значение |
|---|---|
| Направление | характер аккаунта: какие заявки берёт, как оценивает, как откликается |
| Система оценки | правила, по которым заявка получает балл и проходит или нет |
| Калибровка | сверка системы оценки с решениями Бориса на реальных заявках |
| Маршрутизатор | правило, какому направлению достаётся заявка |
| Разум | знание, понимание, речь, суждение, память Сары |
| Самостоятельность | по каким темам Сара отвечает сама, а по каким через Бориса |
| Режим тени | Сара работает на живой площадке, но ничего не отправляет |
| Профи-MCP | граница Сары с Профи.ру: инструменты и события |
| Шлюз модели | очередь вызовов Claude с приоритетами и учётом лимита |
| Исходящая очередь | действия наружу с подтверждением и защитой от дублей |
| ADR | запись архитектурного решения: что решили, почему, что отвергли |
| C4 | способ описывать систему уровнями: контекст, контейнеры, компоненты |
| OOUX | способ строить интерфейс от вещей и их связей |
