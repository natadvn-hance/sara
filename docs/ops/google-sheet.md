# Google Таблица Бориса: Сара пишет отклики в «Лог клиентов»

| | |
|---|---|
| Откуда | Борис, 30.10.2026: «можем ли мы подвязать, чтобы она писала данные в таблицу параллельно? Ну там откликнулась и записала по вот такой формуле» |
| Требование | FR-ANL-7 (`docs/spec/2026-10-22-sara-spec-v1.md`), расчёт `docs/product/analytics-metrics.md` |
| Таблица | «Profi.ru трекер лидов», вкладка «📋 Лог клиентов» (пишет Сара), «🔻 Воронка» и «📊 Сводка по месяцам» (формулы Бориса, Сара их не трогает) |
| Код | ядро `apps/core/src/sheet/sync.ts`, расчёт `logRows` в `apps/core/src/pult/analytics.ts`, скрипт таблицы `infra/sheet/sara-sheet.gs` |

## 1. Как это работает

- Сара откликнулась: в конце лога появляется строка. Месяц словом, имя клиента, тип услуги коротко, этап «Отклик», сумма сделки это «от» из отклика, расходы это цена отклика на Профи.ру.
- Дальше Сара обновляет ту же строку: «Переговоры», когда клиент ответил; «В работе», когда созвон назначен или прошёл; «Закрыта» с суммой, когда Борис записал договор в пульте; «Отвалился», когда отказ, клиент пропал или Профи.ру вернул отклик на баланс (тогда расходы 0 и заметка «Вернули на баланс»).
- Ячейку, которую Борис поправил руками, Сара больше не трогает. Строку, которую он удалил, не возвращает.
- Строки те же, что в логе клиентов пульта («Итоги»): одна функция `logRows`, поэтому числа сходятся.
- В таблицу идут только отклики после подключения: старые строки Борис вписал сам. Тестовые заявки (номера от 99, 🧪) в таблицу не идут никогда.

Устройство:

- В таблице живёт скрипт (Apps Script), развёрнутый как веб-приложение. Ядро раз в минуту шлёт ему POST с секретом и строками, которые изменились.
- Скрипт находит строку по невидимой метке Google (developer metadata, ключ `sara`, значение номер заказа). Метка едет со строкой, если выше вставили строки.
- Скрипт пишет ячейку, только если в ней то, что Сара писала в прошлый раз (`expect`). Иначе отвечает, что ячейку оставил (`kept`), и ядро запоминает её как ячейку Бориса (`sheet_row.boris`).
- Новая строка вставляется сразу под последней заполненной (`insertRowAfter`), то есть внутрь диапазонов формул «Воронки» и «Сводки» (у Бориса `A3:A102`), и диапазоны растягиваются сами.
- Очередь это разница между тем, что Сара знает, и тем, что она записала (`sheet_row.written`): ничего не теряется при перезапуске. Сбой Google не мешает работе Сары: попытка повторяется через 1, 2, 4... минуты, но не реже раза в 30 минут. Запрос, ответ на который потерялся, безопасно повторить: строка уже с меткой, второй не будет.
- «Состояние» в пульте: карточка «Google Таблица». Красная, если строка ждёт записи дольше 15 минут, с причиной на русском.

## 2. Шаги для Бориса

1. Открой таблицу «Profi.ru трекер лидов», меню «Расширения» → «Apps Script».
2. В редакторе сотри всё и вставь текст из файла `sara-sheet.gs`, который тебе пришлют (секрет в нём уже вписан). Нажми «Сохранить».
3. Справа вверху «Развернуть» → «Новое развертывание» → шестерёнка → «Веб-приложение». «Выполнять как»: от моего имени, «У кого есть доступ»: все. «Развернуть», потом «Разрешить доступ» к таблице (если Google напишет, что приложение не проверено: «Дополнительно» → «Перейти»).
4. Скопируй «URL веб-приложения» (кончается на `/exec`) и пришли его. Через пару минут в пульте, «Ещё» → «Состояние», появится «Google Таблица: связь есть».

С этого момента новые отклики Сара пишет сама: руками их больше не вписывай, иначе будет две строки на один отклик.

## 3. Для разработки: выкладка

1. На Маке: `pnpm --silent sheet:script ~/Desktop/sara-sheet.gs`. Команда пишет скрипт со свежим секретом и печатает строку `SARA_SHEET_SECRET=...`.
2. Файл `sara-sheet.gs` отдать Борису (шаг 2 выше). Секрет только в его скрипте и на сервере: в репозиторий, Telegram-сводки и журналы не класть. После передачи файл с Мака удалить.
3. На сервере в `/opt/sara/.env` (600) дописать `SARA_SHEET_SECRET=...` и, когда Борис пришлёт ссылку, `SARA_SHEET_URL=https://script.google.com/macros/s/.../exec`. Перезапустить core: `cd /opt/sara && docker compose -f infra/compose.prod.yml --env-file .env up -d core`.
4. Проверить: «Состояние» показывает «Google Таблица», в логах core нет `sheet sync failed`.

Новый секрет: повторить шаг 1, Борис заменяет текст скрипта и делает «Управление развертываниями» → карандаш → «Новая версия» (ссылка остаётся прежней), секрет на сервере заменить.

Отключить: убрать обе строки из `.env` и перезапустить core. Таблица остаётся как есть.

## 4. Колонки

| Колонка | Что пишет Сара |
|---|---|
| Месяц | месяц отклика по Москве, словом («Октябрь») |
| Клиент | имя клиента с Профи.ру |
| Тип услуги | что Борис назвал в пульте у клиента; иначе коротко по заказу: Сайт, Консультация, Стратегия, SEO, Директ, Таргет, Авито, Лидогенерация, Аудит, Парсинг, Маркетолог; иначе категория заказа |
| Этап воронки | Отклик, Переговоры, В работе, Закрыта, Отвалился (как в выпадающем списке Бориса) |
| Сумма сделки, ₽ | сумма договора, когда Борис записал его в пульте; до этого «от» из отклика; у закрытой сделки без суммы пусто |
| Расходы Профи.ру, ₽ | сколько Профи.ру списал за отклик; 0, если вернул на баланс |
| LTV клиента, ₽ | сумма договора у закрытой сделки, иначе пусто |
| Заметка | заметка Бориса у клиента в пульте; «Вернули на баланс», если отклик вернули, а заметки нет |

## 5. Формулы Бориса: что заметили при подключении

Сара их не меняет. Борис решает сам.

- «Воронка», строки «Переговоры» и «В работе». Сейчас «Переговоры» считает «Ответ» + «Переговоры» + «Закрыта», а «В работе» считает «Переговоры» + «Закрыта». Строки с этапом «В работе» (Сара ставит его, когда назначен созвон) не попадают ни в одну из двух. Если нужно, чтобы попадали:
  - «Переговоры»: `=COUNTIF('📋 Лог клиентов'!D3:D;"Переговоры")+COUNTIF('📋 Лог клиентов'!D3:D;"В работе")+COUNTIF('📋 Лог клиентов'!D3:D;"Закрыта")`
  - «В работе»: `=COUNTIF('📋 Лог клиентов'!D3:D;"В работе")+COUNTIF('📋 Лог клиентов'!D3:D;"Закрыта")`
  - Если таблица не принимает `;`, заменить на `,`.
- Диапазоны формул кончаются на строке 102. Строки Сары вставляются внутрь и растягивают их. Строки, вписанные руками в пустые строки ниже, их не растягивают: когда лог дойдёт до 102-й строки, ручные строки ниже перестанут считаться. Надёжнее открытые диапазоны: `D3:D` вместо `D3:D102`.

## 6. Пределы

- Метки строк у Google ограничены объёмом (около 30 000 знаков на таблицу): это порядка двух тысяч откликов. Когда подойдём к пределу, лог можно разбить по годам.
- Если отсортировать лог «Данные → Сортировка», метки могут остаться на старых строках. Сара тогда не перезапишет чужие данные (пишет только в ячейку, где её прежнее значение), но может перестать обновлять часть своих строк. Лучше не сортировать, а фильтровать.
