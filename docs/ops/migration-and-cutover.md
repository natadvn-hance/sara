# Перенос данных и переключение с v1

| | |
|---|---|
| Версия | 1.0, 22.10.2026 |
| Связано | спецификация раздел 15; ADR-019, ADR-021, ADR-022; инструкция RB-13 |
| Главное правило | в каждый момент клиенту пишет только одна Сара |

## 1. Откуда что берём

| Источник | Что там | Как берём | Когда |
|---|---|---|---|
| База v1 `profi-leads.db` на сервере v1 (SQLite) | 4369 заявок, оценки, решения Бориса, отклики, траты, статусы, тексты, отправленные Сарой v1 | копия файла только на чтение, скрипт переноса | M2 (заявки и траты), M4 (тексты Сары v1) |
| Журнал v1 `~/logs/profi-lead-bot.log` | время событий, сбои | только для разбора, не переносим | |
| Площадка Профи.ру | вся история чатов всех аккаунтов | `profi.backfill_chats` в службе Профи-MCP | M4 |
| Борис | что знает о Hance, ответы на типовые вопросы | интервью карточками | M4-M5 |

Сервер v1 и папку v1 не меняем: копия базы снимается командой только
чтения (`sqlite3 .backup` в отдельный файл) и переносится на Мак.

## 2. Что куда

| v1 | Новая Сара | Правило |
|---|---|---|
| заявка (номер заказа) | `lead` | номер заказа как есть; текст и имя клиента по классу П (словарь данных) |
| оценка v1 | `lead_score` с направлением `hance-marketing`, версия оценки `v1-legacy` | для калибровки и сравнения, не для решений |
| решение Бориса (откликнуться, пропустить) | событие `lead.decided` с актором `boris` | материал калибровки направления |
| отклик и трата | `spend`, событие `bid.sent` | сумма и баланс как в v1 |
| статус переписки | `deal.stage` | таблица соответствия пишется в M2 по реальным значениям базы |
| эскалации v1 (9 старых) | `deal.owner = boris`, задача «решить» | закрываются одним решением Бориса после переключения |
| текст, отправленный Сарой v1 | признак для разделения авторов | см. раздел 3 |

## 3. Разделение авторов в истории

В чате Профи.ру сообщения специалиста пишут и Борис, и Сара v1 с одного
аккаунта. Голос Бориса нельзя учить на текстах Сары v1 (FR-TRAIN-1).

1. Сообщение со стороны клиента: `author = client`.
2. Сообщение со стороны специалиста, совпадающее с текстом, который
   отправила v1 (по базе v1: текст и время в пределах 10 минут):
   `author = sara_v1`.
3. Остальные сообщения специалиста: `author = boris`.
4. Спорные (частичное совпадение текста): `author = unknown`, в тренажёр
   и образцы речи не идут, Борис может разметить пачкой.

Итог проверяется выборкой: Борис смотрит 20 случайных «своих» сообщений
и подтверждает, что это он.

## 4. Переключение по частям

| Этап | Новая Сара | v1 | Как убедиться |
|---|---|---|---|
| 0. Тень (M1-M6) | читает, оценивает, пишет черновики; флаги `outbound.*` выключены | работает как сейчас | черновики сравниваются с решениями Бориса |
| 1. Лента и отклики | `outbound.bids` включён; карточки в новом боте | Борис не пользуется очередью v1; в v1 `npm run pause payments on` | неделя без двойных откликов |
| 2. Разговоры | `outbound.messages` включён для новых клиентов; затем для текущих по одному | в v1 `npm run pause on` (исходящие на паузе, чтение идёт) | неделя: 0 ответов поверх, 0 дублей |
| 3. Выключение v1 | работает полностью | службы v1 остановлены, сервер и база сохранены на месяц | 30 дней без отката |
| 4. Уборка | | архив v1 и v2, копии с секретами в архив, все секреты меняются | |

**Вариант раннего переключения** (дорожная карта, раздел 4): этап 1
сразу после M3, этап 2 после M4-M5.

## 5. Откат

| С какого этапа | Как | Сколько времени |
|---|---|---|
| 1 | выключить `outbound.bids`; в v1 `npm run pause payments off` | минута |
| 2 | выключить `outbound.messages`; в v1 `npm run pause off`; v1 перечитает чаты и продолжит | минута |
| 3 | запустить службы v1 на старом сервере; новая Сара в тень | 10 минут |

## 6. Риски переноса

| Риск | Мера |
|---|---|
| Две сессии одного аккаунта (сервер v1 и новый сервер) выбивают друг друга | проверяется в первые 48 часов M1 (предположение A3); если да, новая Сара до M7 читает только по расписанию |
| Обе Сары пишут одному клиенту | флаги по частям и пауза v1 до включения отправки; тест E8 |
| Неверный автор в истории | правило раздела 3, выборочная проверка Борисом |
| Значения статусов v1 не совпадают с этапами | таблица соответствия по реальной базе, нераспознанное в `dormant` с задачей Борису |
