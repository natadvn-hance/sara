# Перенос данных и переключение с v1

| | |
|---|---|
| Версия | 1.1, 25.10.2026 (1.0 от 22.10.2026) |
| Связано | спецификация разделы 12 и 15; дизайн M7 `docs/superpowers/specs/2026-10-25-m7-pult-design.md`, раздел 9; ADR-019, ADR-021, ADR-022; инструкция RB-13 |
| Главное правило | в каждый момент клиенту пишет только одна Сара |

## 0. Что изменилось в версии 1.1

24.10.2026 в 06:23 UTC Борис выключил v1 насовсем («Ей больше не пользуюсь»). На старом сервере службы `sara-daemon`, `sara-telegram`, `sara-admin` и таймеры `sara-telegram-watchdog`, `sara-telegram-restart` остановлены и выключены; файлы, база и журналы v1 на месте. Новая Сара с этого момента единственная работает с аккаунтом Профи.ру, но в тени: карточки заявок приходят, откликов и сообщений клиентам нет.

Поэтому:
- переключение больше не начинается с паузы v1: v1 уже молчит, Борис подтверждает это одним нажатием на экране «Переключение» (проверка К7);
- откат по умолчанию это возврат новой Сары в тень, а не запуск v1; запуск v1 остаётся аварийным путём до архива (раздел 5);
- части переключения это отдельные защищённые флаги `cutover.*` поверх пауз (дизайн M7, разделы 6.2 и 9.2): пауза меняется каждый день, переключение части один раз и только при зелёных проверках; общий путь настроек, «Вернуть» в истории и слова в боте эти флаги не меняют;
- заявки и траты v1 переносятся в отдельную таблицу `core.legacy_lead` без имён и текстов клиентов (раздел 2);
- клиенты, которых вела v1 (9 старых эскалаций и незакрытые разговоры), сейчас ведёт только сам Борис; их разбор входит в переключение (раздел 4, этап 4).

## 1. Откуда что берём

| Источник | Что там | Как берём | Когда |
|---|---|---|---|
| База v1 `profi-leads.db` на старом сервере (SQLite) | 4369 заявок, оценки, решения Бориса, отклики, траты, статусы, тексты, отправленные Сарой v1 | копия файла только на чтение, скрипт переноса | M4 (переписка и авторство, `pnpm history:export --v1`), M7 (заявки, решения, траты, эскалации, `pnpm import:v1`) |
| Журнал v1 `~/logs/profi-lead-bot.log` | время событий, сбои | только для разбора, не переносим | |
| Площадка Профи.ру | вся история чатов всех аккаунтов | `profi.backfill_chats` в службе Профи-MCP | M4 |
| Борис | что знает о Hance, ответы на типовые вопросы | интервью карточками | M4-M5 |

Сервер v1 и папку v1 не меняем: копия базы снимается командой только
чтения (`sqlite3 .backup` в отдельный файл) и переносится на сервер новой Сары в папку данных с правами 600; в репозиторий и в образ она не попадает и удаляется после переноса.

## 2. Что куда

| v1 | Новая Сара | Правило |
|---|---|---|
| заявка (номер заказа), оценка, решение Бориса, отклик и трата, ответил ли клиент | `core.legacy_lead` (класс Н) | номер заказа, когда найдена, категория, город, балл v1, решение, статус v1, время и цена отклика, ответил ли клиент, назначен ли созвон; без имени и текста клиента; заказ, который есть и в `core.lead`, в итогах берётся из `core.lead` |
| статус переписки | `legacy_lead.status_v1` | таблица соответствия пишется по реальным значениям базы; неизвестное как `unknown`, считается только в «заявках» |
| эскалации v1 (9 старых и все без «беру сам») | задачи `v1_client` к разговорам M4 | разбираются одним экраном после M4 (раздел 4, этап 4) |
| текст, отправленный Сарой v1 | признак для разделения авторов | см. раздел 3 |

## 3. Разделение авторов в истории

В чате Профи.ру сообщения специалиста пишут и Борис, и Сара v1 с одного
аккаунта. Голос Бориса нельзя учить на текстах Сары v1 (FR-TRAIN-1).

1. Сообщение со стороны клиента: `author = client`.
2. Сообщение со стороны специалиста, совпадающее с текстом, который
   отправила v1 (по базе v1: текст и время в пределах 10 минут):
   `author = sara_v1`.
3. Остальные сообщения специалиста: `author = boris`.
4. Спорные (частичное совпадение текста): `author = unknown`, в тренажёр
   и образцы речи не идут, Борис может разметить пачкой.

Итог проверяется выборкой: Борис смотрит 20 случайных «своих» сообщений
и подтверждает, что это он. Сообщения специалиста после 24.10 06:23 UTC,
которых нет в исходящей очереди новой Сары, написал Борис (v1 стоит);
это включается частью 3 переключения (`conv.v1_writes` выключено).

## 4. Переключение по частям

Каждая часть включается кнопкой Бориса на экране «Переключение» пульта (`/settings/switch`) только при зелёных проверках этой части и выключается одной кнопкой «Вернуть в тень». Проверки К1-К12 и как они меряются: дизайн M7, раздел 9.3; отчёт `pnpm report:cutover`.

| Этап | Часть, флаг | Условия (проверки) | Как убедиться после |
|---|---|---|---|
| 0. Тень | все `cutover.*` выключены, `conv.v1_writes` включено | | черновики сравниваются с решениями Бориса |
| 1. Карточки заявок | `pipeline.leads` (включено 24.10) | | карточки меньше 2 минут у 90% |
| 1б. Черновики разговоров в тени | `pipeline.conversations` (M4, включает выкладка M4) | | черновики приходят, клиентам ничего не уходит |
| 2. Отклики | `cutover.bids` и пауза `outbound.bids` | К4, К5, К8, К9 (К6 до 5 откликов «мало данных», не блокирует); исправления пути отклика после проверки M2 слиты и выложены | неделя без двойных откликов и без откликов без «да» |
| 3. Сара v1 больше не пишет | `conv.v1_writes` выключено | выложен PR 13 M7 (правило отправки `messagesAllowed` в `queueMessage`); К7 (нажатие Бориса «Да, v1 выключена») | сообщения Бориса в чатах определяются как его; клиентам по-прежнему ничего не уходит, пока не включён этап 4 |
| 4. Разговоры `own` | `cutover.messages = own` и пауза `outbound.messages` | К1, К2, К3, К7, К8, К9, К10 | неделя: 0 ответов поверх, 0 дублей (К12) |
| 4б. Клиенты времён v1 | задачи `v1_client`: «Сара ведёт», «Беру сам», «Закрыть» | все разобраны | ни одного открытого разговора v1 без владельца |
| 5. Разговоры `all` | `cutover.messages = all` | К12 после 7 дней `own` | неделя: 0 ответов поверх, 0 дублей |
| 6. v1 насовсем | ручная отметка | 30 дней после этапа 5 без отката | архив папки v1 и копий с секретами на старом сервере, смена секретов (RB-14), токен старого бота отозван у @BotFather; **старый сервер не удаляется**: на нём работает VPN Бориса |

**Порядок и раннее переключение.** Отклики (этап 2) не ждут M4-M6: их можно включать, как только проверки зелёные. Разговоры (этапы 3-5) после M4 и PR 13 M7. Текст Бориса через Сару уходит клиенту только с этапа 4 (до этого Борис пишет сам на Профи.ру), а после него и на паузе «Пишет клиентам».

**Если отклики включили до выкладки M7** (раннее переключение или пробный отклик M2 через `pnpm bids:on`): флаг `cutover.bids` создаётся выключенным всегда, и Сара присылает Борису одно сообщение, что отклики теперь включаются на экране «Переключение». Если отклики работали по-настоящему, разработка в той же выкладке выполняет `pnpm cutover bids on --force "отклики работали до M7"`. Пробный отклик M2 после выкладки: `pnpm cutover bids on --force "пробный отклик M2"`, отклик, `pnpm cutover bids off`.

## 5. Откат

| С какого этапа | Как | Сколько времени |
|---|---|---|
| 2 | «Вернуть в тень» у части «Отклики» (`cutover.bids = false`); отклик в отсрочке и в очереди не уйдёт | меньше 10 секунд |
| 4, 5 | «Вернуть в тень» у части «Разговоры» (`cutover.messages = off`) или `all` → `own`; ход в паузе перед отправкой перечитывает правило | меньше 10 секунд |
| 3 | `conv.v1_writes` включить обратно, только если v1 запускается снова | меньше 10 секунд |
| аварийный запуск v1 (до этапа 6) | 1) этапы 2-5 в тень; 2) на сервере новой Сары остановить контейнер службы Профи-MCP (`docker compose stop profi-node`) и проверить, что не осталось ни одного процесса Chromium с профилем аккаунта: выключать браузер отдельного аккаунта служба пока не умеет, а пауза аккаунта браузер не останавливает (два браузера с одной сессией выбивают друг друга); 3) на старом сервере `systemctl enable --now sara-daemon sara-telegram sara-admin sara-telegram-watchdog.timer sara-telegram-restart.timer`; 4) `npm run login` на Маке, если сессия v1 умерла; 5) `conv.v1_writes` включить | 15-30 минут, разработка по слову Бориса |
| обратно с v1 на новую Сару | 1) на старом сервере `systemctl disable --now` тех же служб и таймеров и проверить, что браузер v1 не работает; 2) запустить `profi-node`; 3) если сессия умерла, войти живым экраном пульта; 4) К7 нажать снова; 5) этапы включать заново по разделу 4 | 15-30 минут |

Откат проверяется учением перед этапами 2 и 4 (`pnpm cutover:drill`, проверка К9).

## 6. Риски переноса

| Риск | Мера |
|---|---|
| Две сессии одного аккаунта выбивают друг друга | v1 остановлена 24.10; при аварийном запуске v1 сначала останавливается контейнер `profi-node` новой Сары, при возврате сначала службы v1 (раздел 5) |
| Обе Сары пишут одному клиенту | v1 стоит; часть «Разговоры» требует отметки К7; при запуске v1 этапы 2-5 сначала в тень; тест E8 |
| Касание паузы, «Вернуть» в истории настроек или слова в боте выводят Сару из тени | паузы не нажимаются, пока часть не переключена; ключи переключения защищены (`PROTECTED_KEYS`): их меняют только экран «Переключение» при зелёных проверках и команда разработки с причиной |
| Клиенты v1 без присмотра с 24.10 | задачи `v1_client` во Входящих и блок на экране «Переключение» (этап 4б) |
| Неверный автор в истории | правило раздела 3, выборочная проверка Борисом |
| Значения статусов v1 не совпадают | таблица соответствия по реальной базе, неизвестное как `unknown` |
