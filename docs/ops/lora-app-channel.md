# Канал Лоры в голосовом приложении

| | |
|---|---|
| Что | Лора отвечает Борису в приложении `sara.hance.pro/talk` так же, как в Telegram: та же сессия Claude Code, та же память |
| Решение | ADR-028 (Лора по умолчанию, Сара по вызову; Борис, 07.11.2026) |
| Кто ставит | сессия разработки Лоры (её проект, её запуск); ядро Сары и приложение готовы |

## Как устроено

Приложение и ядро Сары делают всё, кроме самой Лоры:

- запись голоса распознаёт ядро (whisper.cpp), Лоре приходит уже текст;
- «позови Сару» и «позови Лору» ядро ловит само, Лоре такие слова не
  приходят;
- приветствие «Борь, я на связи.» приложение говорит само;
- ответ Лоры приложение показывает текстом и читает голосом baya (служба
  `voice` Сары, та же модель Silero, что у Лоры); числа, суммы, время и
  ссылки ядро делает произносимыми само.

Лоре нужен второй канал рядом с Telegram: программа, которая забирает слова
Бориса из ядра и отдаёт её ответ обратно.

## Адреса ядра

Все запросы с заголовком `x-sara-lora-token: <SARA_LORA_TOKEN>`: тот же
ключ, которым Лора уже пишет итоги встреч (`docs/ops/lora-meeting-result.md`).
Без ключа или с чужим 401; если ключ на сервере Сары не задан, 503.

**`GET https://sara.hance.pro/api/lora/app/next`**: долгое ожидание до 25
секунд.
- `200 {"talk": "<uuid>", "text": "что у меня завтра", "voice": true, "at": "2026-11-07T15:00:00.000Z"}`:
  слова Бориса (`voice`: сказаны голосом).
- `204`: слов не было, спросить снова сразу.
- Канал спрашивает без перерыва. Канал, который не спрашивал полторы
  минуты, приложение считает не на связи и говорит Борису «Лора сейчас не
  на связи в приложении».

**`POST https://sara.hance.pro/api/lora/app/reply`** с телом
`{"talk": "<uuid из next>", "text": "ответ"}` (до 4000 знаков):
- `200 {"ok": true, "waiting": true}`: приложение ждало этот ответ и
  покажет его;
- `{"ok": true, "waiting": false}`: приложение уже не ждало (прошло больше
  шести минут или сервер перезапускался), ответ виден только в истории.

## Что поставить Лоре

1. MCP-сервер канала (как плагин Telegram), например `hance-app`:
   - цикл `next`; каждое слово Бориса отдаёт в сессию событием канала
     (`notifications/claude/channel`) с текстом и метками
     `source="hance-app"`, `talk="<uuid>"`, `voice="true|false"`;
   - инструмент `app_reply(talk, text)`, который делает `reply`.
2. Запуск Лоры с этим каналом рядом с Telegram (`--channels`; для своего
   канала, пока он не в списке разрешённых, флаг разработки каналов).
3. В `CLAUDE.md` Лоры раздел о приложении:
   - сообщение `<channel source="hance-app" talk="...">` это Боря в
     голосовом приложении; отвечать только через `app_reply` с тем же
     `talk`, не через Telegram;
   - отвечать как голосом: коротко, без разметки и списков, до 900 знаков
     (длиннее приложение покажет текстом, а голосом прочитает начало);
   - числа можно цифрами, ядро прочитает их словами;
   - то, что нужно глазами (ссылки, списки), можно дублировать в Telegram.

## Проверка

1. На сервере: `curl -s -o /dev/null -w '%{http_code}' -H "x-sara-lora-token: $SARA_LORA_TOKEN" https://sara.hance.pro/api/lora/app/next`
   через 25 секунд даёт `204`.
2. В приложении сказать Лоре «проверка связи»: ответ приходит текстом и
   голосом baya.
3. Остановить канал: через полторы минуты приложение отвечает «Лора сейчас
   не на связи в приложении».
