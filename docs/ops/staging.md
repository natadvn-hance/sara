# Тестовый стенд Сары

| | |
|---|---|
| Версия | 0.1, 30.10.2026 |
| Статус | план и первая сборка; на сервер только после «да» Бориса |
| Зачем | Борис 30.10.2026: «создать тестовую среду, чтобы отправлять отклики, но тестовые и бесплатные» |

## Что это

Вторая Сара на том же сервере 143.246.42.121: тот же код ядра и пульта (любая ветка), но вместо Профи.ру
работает Профи.ру понарошку. Отклик «уходит» бесплатно, кошелёк условный, клиентов играет модель или Борис.
Свой бот в Telegram, свой пульт `https://test.sara.hance.pro`, своя база. Боевая Сара, её база, узел и
профиль браузера не трогаются.

## Как устроено

```
Интернет ─► caddy боевой Сары (443) ─┬─► sara.hance.pro ─► боевая Сара (как сейчас)
                                     └─► test.sara.hance.pro ─► web стенда ─► core стенда
                                                                                │  MCP, события
                                                                         stand (Профи.ру понарошку,
                                                                         клиенты-симуляторы)
```

Проект Docker Compose `sara-staging` (`infra/compose.staging.yml`), четыре службы:

| Служба | Что | Откуда код |
|---|---|---|
| `core` | ядро и бот, как в бою (`NODE_ENV=production`) | ветка, которую проверяем |
| `web` | пульт, отдаёт статику и `/api` ядра по http внутри Docker | та же ветка |
| `stand` | фальшивый Профи.ру (`apps/profi-node/src/fake`) + клиенты-симуляторы + страница `/stand/` | `main` или ветка, если в ней есть стенд |
| `postgres` | своя база стенда | образ тот же, что в бою |

Наружу стенд не открывает ни одного порта. Единственная правка боевой части: Caddy боевой Сары читает
дополнительные адреса из папки `/opt/sara-sites` (строка `import` в `infra/caddy/Caddyfile`) и входит в сеть
`sara-stage-link`, где живёт `web` стенда. Пока папка пуста, Caddy только пишет предупреждение (проверено на
caddy 2.10). Применяется обычной выкладкой боевой Сары, пересоздаётся только контейнер caddy (секунды).

### Своя база: отдельный контейнер, а не схема в боевом

Оценила оба способа. Отдельный Postgres на том же образе `pgvector/pgvector:pg16`: образ уже на диске (0 байт
сверху), данные стенда десятки мегабайт, память около 50-80 МБ при `shared_buffers=32MB`. Своя база внутри
боевого контейнера экономит эти 50-80 МБ, но код любой ветки начинает ходить к боевому Postgres: ошибка в
адресе, тяжёлый запрос или пул соединений DBOS задевают бой, а сброс стенда требует прав в боевой базе.
Выбор: отдельный маленький контейнер.

### Сколько стоит серверу

На 30.10: диск 30 из 40 ГБ (свободно 7,8 ГБ), память 3,9 ГБ (доступно около 1,4 ГБ и 6 ГБ подкачки),
4 процессора. Кэш сборки Docker занимает 12,9 ГБ и почти весь освобождаем.

| | Диск | Память (потолок) |
|---|---|---|
| образ core стенда (общие слои с боевым) | около 1-1,5 ГБ | 1 ГБ, 1,5 процессора |
| образ stand (поверх образа core) | около 0,2 ГБ | 512 МБ |
| web | около 0,1 ГБ | 64 МБ |
| postgres | 0 (тот же образ) | 256 МБ |

У каждой службы потолок памяти и процессора, чтобы стенд никогда не отнял их у боя. Перед первым запуском
советую `docker builder prune -f --keep-storage 4GB` (освободит около 8 ГБ кэша сборки; это не трогает
работающие контейнеры, но следующая боевая выкладка может собираться на несколько минут дольше). Только с
«да» Бориса.

## Профи.ру понарошку

Служба `stand` поднимает тот же фальшивый Профи.ру, что e2e-тесты, по тому же контракту C2 (MCP и события).
Добавлено только окружение:

- **Состояние на диске.** Заказы, чаты и кошелёк переживают перезапуск службы (файл в томе `stand-data`).
- **Отклик в чат.** Отклик сразу появляется в чате заказа, как на Профи.ру, и с него начинается переписка.
- **Кошелёк условный.** Стартует с 5000 ₽, отклик «списывает» цену заказа, кнопка «Пополнить» на странице.
- **Страница стенда** `https://test.sara.hance.pro/stand/` (вход тем же паролем, что пульт стенда):
  подкинуть заказ, чаты с клиентами, написать за клиента, выбрать, как клиент себя ведёт, закрыть заказ,
  запустить сценарий.

## Заказы как настоящие

- **Копии реальных.** Команда `import-real` читает последние 300 заказов из `core.lead` боевой базы
  (`pg_dump`/`psql` в режиме только чтения), заменяет имя клиента, телефоны, почты и ссылки на выдуманные
  (по `redact` из ядра, ADR-016) и кладёт в том стенда на сервере. В репозиторий и с сервера ничего не уходит.
  У копии новый номер (`8…`), чтобы ссылка из карточки не вела на настоящий заказ.
- **Выдуманные.** 18 обезличенных образцов из `tests/fixtures/orders`.
- «Подкинуть заказ»: кнопка на странице стенда или `pnpm staging order [real|sample]`.

## Клиенты-симуляторы

Как клиент ведёт себя в чате, выбирается для каждого заказа (по умолчанию на странице стенда):

| Поведение | Что делает | Модель |
|---|---|---|
| отвечает | играет клиента по персоне, отвечает на каждое наше сообщение | haiku |
| просит цену | сразу спрашивает цену и сроки, без цены дальше не идёт | haiku |
| просит созвон | просит созвониться, выбирает время из предложенного | haiku |
| молчит | читает отклик и молчит (проверка напоминаний) | нет |
| уходит к другому | вежливо пишет, что выбрал другого | нет |
| по сценарию | реплики из файла сценария | нет |
| пишу сам | Борис пишет за клиента на странице стенда | нет |

- Модель играет клиента по готовой роли `roles/trainer-client` (haiku, M5) и персоне. Персоны: шесть
  выдуманных в `apps/stand/personas.json` плюс обезличенные персоны тренажёра из боевой базы, если они уже есть.
- Экономия: модель зовётся только когда клиенту есть что ответить; потолок 40 ответов в день на весь стенд
  (`STAND_CLIENT_DAILY_LIMIT`) и 8 на один чат. После потолка клиент молчит, страница стенда это показывает.
- Как живой клиент: «прочитал» через 5-15 секунд, «печатает» перед ответом; первый ответ после отклика
  через 3-4 минуты (чтобы серия вдогонку успела уйти), дальше через 30-60 секунд.

## Весь путь как в бою

Ядро и пульт ветки работают без правок: карточка заявки в тестовом боте, «Откликнуться», отклик и серия
вдогонку уходят в Профи.ру понарошку, клиент отвечает, черновик ответа с «Отправить», напоминания, встречи,
пульт. Настройки стенда при первом запуске и сбросе копируются с боя (только чтение: `core.setting`,
правила `core.direction_version`, профиль `core.direction_profile`), кроме:

- отклики, сообщения клиентам и карточки включены (`outbound.bids`, `outbound.messages`, `pipeline.leads`,
  `pipeline.conversations`): всё бесплатно и понарошку;
- ночная школа выключена (`school.on`), чтобы не тратить общий лимит Claude;
- тихие часы карточек сняты, откликов в день до 100.

Разум: копия `/opt/sara-mind` в `/opt/sara-staging/mind`, только чтение.

## Команды

С Мака (каждая идёт на сервер по ssh с повторами):

```bash
pnpm staging up <ветка>        # собрать и запустить стенд на ветке (по умолчанию main)
pnpm staging up <ветка> --reset   # то же и начать с чистой базы
pnpm staging reset             # стереть стенд и начать заново; пароль, бот и токены остаются
pnpm staging scenario apps/stand/scenarios/full-day.json   # прогнать сценарий из файла
pnpm staging order real        # подкинуть копию реального заказа (sample: выдуманный)
pnpm staging import-real       # обновить копии реальных заказов
pnpm staging status            # что запущено, какая ветка, сколько ответов модели-клиента сегодня
pnpm staging down              # остановить стенд и убрать его адрес из Caddy
```

Сброс стирает базу стенда, процессы DBOS и состояние Профи.ру понарошку. Остаются пароль пульта, привязка
бота (`core.owner_auth`), шаг мастера и `secrets.json` (токены бота и Claude), чтобы не проходить мастер
заново. Ветки с разными миграциями между собой лучше переключать с `--reset`.

## Первый запуск (после «да» Бориса)

1. Борис: запись DNS `test.sara.hance.pro` типа A на 143.246.42.121 (reg.ru).
2. Борис: новый бот в BotFather (например `@hancesaratestbot`). Токен вводится только в мастере пульта
   стенда, на сервер; боевой токен стенду никогда не даётся (два бота на одном токене ломают друг друга).
3. Выкладка боевой Сары с этой правкой Caddy (`pnpm deploy`), чтобы появились папка адресов и сеть.
4. `pnpm staging up main`: клоны в `/opt/sara-staging/{app,stand}`, `.env` стенда с новыми паролями
   (права 600, только на сервере), сборка, копия настроек с боя, копии заказов, адрес в Caddy.
5. Борис проходит мастер на `https://test.sara.hance.pro`: пароль, бот, токен Claude. Токен Claude можно
   не вводить: `pnpm staging up --claude-from-prod` копирует боевой токен внутри сервера (та же подписка).
6. Борис пишет `/start` тестовому боту, жмёт «Подкинуть заказ» на странице стенда, дальше по инструкции.

## Что ещё не так, как в бою

- Профи.ру понарошку не умеет живой экран, ленту и страницы платежа: эти части проверяются только на бою.
- Переписка стенда не учит боевую Сару: уроки остаются в базе стенда, разум у стенда только для чтения.
- Лимит Claude общий с боем: стенд тратит его, когда Борис подкидывает заказы и когда отвечает модель-клиент.
