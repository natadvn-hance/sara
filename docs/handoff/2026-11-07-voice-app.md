# Голосовое приложение: передача дел (07.11.2026)

Борис 07.11: приложение на iPhone, чтобы говорить с Сарой голосом, с
вызовом по боковой кнопке. Ветка `feat/voice-app`, решение ADR-028,
требование FR-NOTIF-5, история ST-M7-18, инструкция `docs/ops/voice-app.md`.

## Где что

| Что | Где |
|---|---|
| Страница `/talk` (отдельный вход сборки, свой манифест и иконки) | `apps/web/talk.html`, `apps/web/src/talk/`, `apps/web/public/talk*` |
| Адреса `/api/talk` (вход пульта, проверка до чтения тела) | `apps/core/src/talk/routes.ts` |
| Ответы, которых ждёт приложение (память ядра, 15 минут) | `apps/core/src/talk/answers.ts` |
| Текст для голоса: числа словами, без ссылок и разметки | `apps/core/src/talk/speech.ts` |
| Клиент службы голоса, WAV в MP3 через ffmpeg ядра | `apps/core/src/talk/voice.ts` |
| Служба `voice` (Silero v5_5_ru, xenia) | `infra/voice/server.py`, `infra/docker/voice.Dockerfile`, `infra/compose.prod.yml` |
| Маршрут Caddy `/talk` | `infra/caddy/Caddyfile` |

## Что важно знать

- **Один путь слов.** `onBorisMessage` в `apps/core/src/app.ts` общий для
  бота и приложения. Слова из приложения несут `talk` (id ожидания);
  Секретарь отвечает туда, откуда слова пришли: в Telegram только если
  хоть одно слово хода пришло из Telegram, приложению через `answered`.
- **Карточки с кнопками** инструменты Секретаря шлют в Telegram как
  раньше; `runTool` считает их в `TurnContext.cards`, приложение пишет
  «Кнопки пришли в Telegram и во Входящие пульта».
- **Память сервера.** Модель грузится только на разговор (рабочий
  процесс, выгрузка после 5 минут тишины), не грузится, если свободно
  меньше 800 МБ, контейнер ограничен 1 ГБ и двумя ядрами, ядро ОС при
  нехватке памяти останавливает его первым (`oom_score_adj: 1000`). 07.11 на
  сервере было свободно 0,6-1,9 ГБ: голосовые службы Лоры держат около
  0,85-0,97 ГБ на процесс.
- **Что не проверено до выкладки.** Сама модель v5_5_ru на Маке не
  запускалась: с Мака она качается со скоростью около 14 КБ/с, копии нет.
  Код загрузки тот же, что у Лоры (`torch.package`, `apply_tts`), модель
  при сборке сверяется по той же sha256. После выкладки проверить:
  `docker compose ... exec core node -e` с запросом на `http://voice:7080/speak`
  и `docker stats` для памяти.
- **iOS.** Открыть приложение с экрана «Домой» из «Команд» нельзя, команда
  для кнопки действия ведёт в Safari (`/talk?go=1`). Поведение iOS
  (микрофон и звук без касания) проверяется только на телефоне Бориса:
  симулятора на Маке нет.

## Дальше

- Если Safari с `?go=1` окажется неудобен: команда с «Диктовать текст» и
  отправкой на сервер по отдельному ключу (вариант в ADR-028).

## 12.11.2026: два исправления голоса

Замер приложения: один обмен 15 с. Ядро ответило текстом за 8 мс (задержка
в сети), первая озвучка была холодной (6 с), а распознавание через сокет
Лоры падало каждый раз.

- **Распознавание через сокет Лоры.** Копия голосового в
  `/srv/voice-share/in` получала группу источника (gid 0), а не группу
  папки `voice-share`, и служба отвечала `Permission denied`; Сара падала
  на свой whisper.cpp. Теперь после копирования файл передаётся группе
  папки (`apps/core/src/notify/transcribe.ts`), права 640. Код Лоры не
  менялся. Тест: `apps/core/test/notify/socketDrop.test.ts`.
- **Первая фраза после `/warm`.** Раньше `/warm` только грузил модель.
  Теперь служба голоса после загрузки один раз говорит «Да.» нужным
  голосом (`infra/voice/server.py`); без имени голоса прогреваются оба,
  xenia и baya. Уже прогретый голос не прогревается повторно, сбой прогрева
  не мешает озвучке. Ядро передаёт голос агента: `POST /api/talk/warm?agent=lora`
  (и `?agent=` у `/api/talk`).
- **Что выкладывать.** Образ `core` (оба исправления) и образ `voice`
  (прогрев). Порядок не важен: новое ядро со старой службой голоса и
  наоборот работают, просто без прогрева. Приложению стоит присылать
  `agent` в `/api/talk/warm`.
