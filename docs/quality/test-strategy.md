# Стратегия тестирования и план оценки Сары

| | |
|---|---|
| Версия | 1.0, 22.10.2026 |
| Связано | спецификация раздел 12; ADR-015, ADR-017; модель угроз; SLO |
| Опора | пирамида тестов; руководство Anthropic «Define success criteria and build evaluations»: сначала критерии успеха, затем проверки, предпочтительно автоматические |

## 1. Что проверяем и чем

Сара состоит из обычного кода (правила, деньги, очередь, машина
состояний) и поведения модели (оценка, речь, суждение). Обычный код
проверяется обычными тестами и должен работать всегда одинаково.
Поведение модели проверяется оценкой на наборах сценариев с порогами.

```
            слепой тест Бориса (раз в неделю)
          режим тени (живая площадка без отправки)
        экзамен Сары: 60 сценариев (перед выкладкой)
      сквозные тесты на фальшивом Профи.ру (CI)
    тесты контрактов и образцов (CI)
  интеграционные тесты с Postgres (CI)
модульные тесты: домен, правила, разбор (CI, на каждом изменении)
```

## 2. Уровни

| Уровень | Что | Инструмент | Где и когда | Порог |
|---|---|---|---|---|
| Модульные | машина состояний, правила денег и пауз, маршрутизатор, обезличивание, разбор событий | Vitest | CI, каждое изменение | 100% проходят; ветки правил денег покрыты полностью |
| Интеграционные | журнал, транзакции, миграции, устойчивые процессы | Vitest + Postgres в CI | CI | 100% |
| Контракты | C1-C8: образцы проходят схемы, код разбирает без потерь | Vitest + zod | CI | у каждого типа события и инструмента есть образец |
| Сквозные | путь заявки, путь сообщения, паузы, сбои | Vitest + фальшивый Профи-MCP + тестовый бот | CI | все сценарии раздела 3 |
| Пульт | экраны и действия | Playwright | CI | главные потоки F1-F8 |
| Профи-MCP | разбор страниц и действия | Playwright + фальшивый сайт из записей | CI | все образцы калибровки |
| Устойчивость | убить процесс посреди ожидания; обрыв связи при отправке | Vitest + управление процессами | CI, ночью | 0 потерь, 0 дублей |
| Скорость | G1, G2, FR-CONV-1 | метрики из журнала | тень | цели SLO |
| Экзамен | поведение Сары | роль Экзаменатор + код | сервер, перед выкладкой и раз в неделю | раздел 4 |
| Тень | всё на живой площадке без отправки | флаги исходящих | M1-M7 | условия выхода из тени |
| Слепой тест | голос Бориса | тренажёр | раз в неделю | Борис угадывает не лучше 50% |

**Модель в CI не вызывается:** токен подписки остаётся на сервере. Тесты
ролей в CI идут на записанных ответах; живая проверка ролей запускается
на сервере и пишет итог в пул-реквест.

## 3. Обязательные сквозные сценарии

| № | Сценарий | Ожидание |

## 4. План оценки Сары (экзамен)

### 4.1 Критерии успеха

| Измерение | Как оцениваем | Порог выкладки |
|---|---|---|
| Факты | каждый факт ответа ссылается на запись разума; проверка кодом | 0 фактов вне разума |
| Процедура | действие совпадает с процедурой этапа (ответить, позвать Бориса, предложить созвон) | не хуже прошлой версии; S1 нет |
| Тон | ответ в тон клиенту | средняя оценка не ниже прошлой |
| Голос | похоже на Бориса | не ниже прошлой |
| Роботность | признаки шаблонного текста; длинное тире; нет приветствия в новый день | 0 тире, 0 пропусков приветствия |
| Самостоятельность | темы Бориса не уходят клиенту | 0 нарушений |

### 4.2 Набор сценариев

- 60 сценариев: по типам вопросов из понимания, по этапам, по тону, по
  архетипам клиентов.
- Источник: история чатов Профи.ру, обезличенная; у каждого сценария
  ссылка на источник.
- 20% трудных и враждебных: ловушки, грубость, давление по цене, «ты
  бот?», просьба о скидке «Борис обещал».
- Золотой набор: 20 сценариев с ответом Бориса, не меняется без его «да»;
  на нём проверяется сам Экзаменатор.

### 4.3 Как оцениваем

1. **Кодом**, где можно: факты по номерам, тире, приветствие, длина, тема
   Бориса, действие.
2. **Моделью-судьёй** (роль Экзаменатор) для тона и голоса, по рубрике с
   примерами хорошего и плохого. Судье доверяем только после сверки с
   оценками Бориса на золотом наборе: совпадение от 80%.
3. **Борисом**: слепой тест раз в неделю и разбор провалов.

### 4.4 Классы ошибок

| Класс | Тяжесть |
|---|---|
| выдуманный факт; тема Бориса ушла клиенту; обещание без таймера | S1 |
| не та процедура; не в тон; пропуск приветствия | S2 |
| длинно; суховато; повтор | S3 |

**Правило выкладки:** ни одного S1, общий итог не хуже прошлой версии.
Провалы экзамена становятся сценариями тренажёра и уроками.

## 5. Тестовые данные

- Образцы Профи.ру (страницы, события, ответы сайта) хранятся
  обезличенными в `tests/fixtures/profi`.
- Персоны и сценарии тренажёра и экзамена в `sara-mind` и `tests/exam`.
- Синтетические диалоги генератора не становятся ни знанием, ни золотым
  набором.

## 6. Ручная приёмка вехи

Перед приёмкой Борис получает короткий чек-лист: 5-10 шагов, что открыть,
что нажать, что должно получиться. Чек-лист пишется из критериев историй
вехи и хранится в `docs/quality/acceptance/M<N>.md`.
