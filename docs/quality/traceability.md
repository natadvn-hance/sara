# Трассируемость требований

| | |
|---|---|
| Версия | 1.0, 22.10.2026 |
| Метод | матрица трассируемости (RTM): требование → веха → история → тест |
| Автоматизация | `pnpm trace` в M0 (ST-M0-14) строит матрицу из спецификации, бэклога и тестов; отчёт прикладывается к каждому CI |

## 1. Правила связей

| Звено | Как связано |
|---|---|
| Цель → требование | в спецификации у требования есть цель G1-G7 или сценарий JS |
| Требование → история | в истории строка «Требования: FR-…» |
| История → issue | заголовок issue начинается с `ST-…`, метки `FR-…` |
| Требование → тест | в названии теста номер требования: `it('FR-LEAD-4: два отклика на один заказ невозможны')` |
| Тест → выпуск | отчёт CI сохраняется с номером версии |

Проверки CI: у требования текущей вехи нет теста, это предупреждение; на
ветке выпуска это ошибка. Номер требования в тесте, которого нет в
спецификации, это ошибка.
