## 1. Готово к работе (Definition of Ready)

История берётся в работу, только если:

1. Есть номер `ST-…` и ссылки на требования `FR-*` или `NFR-*`.
2. Сценарий записан словами Бориса: «Когда…, хочу…, чтобы…» или ссылка
   на JS-сценарий.
3. Критерии приёмки в виде «Дано / Когда / Тогда», каждый проверяем
   тестом или показом.
4. Названы контракты, которые история меняет (C1-C8), и данные с классом
   (Н, П, К, С).
5. Для экрана есть каркас или текстовый макет; для уведомления точный
   текст.
6. Фальшивые службы и образцы для тестов есть или входят в историю.
7. Зависимости готовы.
8. История помещается в один рабочий блок (до дня). Иначе делится.
9. Риски для аккаунта Профи.ру, денег и данных клиентов названы.

## 2. Готово (Definition of Done)

### 2.1 История

1. Критерии приёмки выполнены, каждый проверен тестом; у тестов метки
   требований (`FR-…`).
2. Тесты написаны до кода (TDD), CI зелёный: проверки, типы, тесты,
   сборка, поиск секретов, проверка длинного тире.
3. Проверка кода пройдена (отдельная сессия-проверяющий).
4. Контракты и словарь данных обновлены, если менялись.
5. Тексты для Бориса и клиентов по-русски, простым языком, без длинного
   тире.
6. Новый сбой описан в инструкциях на случай сбоя (`docs/ops/runbooks.md`).
7. Коммиты по Conventional Commits.
8. Если менялось поведение Сары: экзамен не хуже прошлой версии.

### 2.2 Веха

1. Все истории вехи готовы по 2.1.
2. Покрытие требований вехи тестами 100% по отчёту трассируемости.
3. Чек-лист приёмки `docs/quality/acceptance/M<N>.md` пройден Борисом.
4. Модель угроз пересмотрена; новые риски в реестре.
5. Инструкции на случай сбоя для новых частей написаны и проверены.
6. Выпуск собран, «Что нового» отправлено Борису.
7. Документ передачи дел обновлён.

### 2.3 Включение в работу (после тени)

1. Условия выхода из тени выполнены (спецификация, раздел 12).
2. Бэкап и восстановление проверены за последние 7 дней.
3. Откат на прошлую версию проверен.
4. Борис дал «да».
