# Разбор ответов Бориса раз в день

| | |
|---|---|
| Версия | 1.0, 02.11.2026 |
| Откуда | Борис, 01-02.11.2026, разбор заказа 95622361: спас разговор, написав сам «как человек», и спросил, что делать с такими данными |
| История | ST-M7-18 в `docs/product/backlog.md`, требование FR-SPEECH-5 |
| Код | `apps/core/src/conversation/replyDigest.ts`, роль `roles/reply-cleaner`, таблица `core.reply_pick` |

## 1. Зачем

Живые ответы Бориса лучший материал для учёбы речи. В разуме 36 образцов из переписок до Сары, живые никто не собирает. Раз в день Сара показывает ему, где он написал не так, как она предложила, и он одним нажатием решает, брать ли это в образцы.

## 2. Что видит Борис

Утром, с 10:00 по Москве, один пост в общей теме без звука: до пяти пар «клиент написал, я предложила, ты ответил», самые непохожие первыми. У каждой пары кнопки «В образцы» и «Не надо». Нажатие убирает кнопки только этой пары и ставит отметку в посте. Если нового нет, поста нет.

Пост показывает ответ ровно таким, каким он ляжет в образец: имена, телефоны, почты и ссылки за метками, опечатки поправлены.

## 3. Что попадает в пост

Отбор делает код, без модели:

- ход ответа на клиента с черновиком Сары, не старше недели;
- после слов клиента и до его следующего сообщения есть сообщения Бориса: вместо черновика или после него. Несколько подряд считаются одним ответом;
- автор `boris` с основанием `say` или `after_cutover`. Старая Сара и голос, который не определён, не попадают;
- ответу не меньше 12 часов, чтобы клиент успел ответить, длина от 16 до 1500 знаков;
- сходство с черновиком ниже `auto.substantial_below` (70%), считает `similarity` по всему ответу;
- заказ не тестовый; имя клиента известно, иначе его нельзя скрыть, и пары нет (NFR-PRIV-2);
- пара ещё не показывалась. Показанная не приходит второй раз, нажал Борис или нет. Не вошедшая сегодня может прийти завтра.

## 4. Опечатки: один дешёвый вызов

Лимит Claude общий с живой Сарой. Один вызов `reply-cleaner` (Haiku, приоритет P3, без более дорогой запасной модели) на весь пост, только в день, когда есть что показать. Модель получает уже скрытые тексты и правит только опечатки. Код проверяет ответ: те же метки и не больше 8% изменённых букв (минимум 3). Ответ, который переписал слова Бориса, не берётся, и пара ждёт другого дня.

Место дня занимается до вызова. На лимите, при сбое модели и при отказе Telegram поста сегодня нет и второго вызова нет, завтра пары придут снова.

## 5. Что делает «В образцы»

Создаёт предложение в разум, строку `core.mind_proposal` в состоянии `new` и файл `mind/proposals/shared/speech/examples/e-l-<хэш>.md`, `status: proposal`, в формате `e-boris-NN`:

- поля `topic` и `tones` из разбора хода, `stages` из стадии сделки, `sources`: `live:<аккаунт>:<сообщение>` и `boris-press:<дата>`;
- `## Клиент` и `## Борис`;
- `## Обещание`, если в ответе есть коммерческое обещание;
- `## Исход`: ответил ли клиент после этого и через сколько, дошло ли до созвона, на дату нажатия.

Код ничего не вливает в подтверждённый разум. Подтверждает только `pnpm mind:accept` в клоне `sara-mind` (FR-MIND-3). Предложение, которое `say` раньше сделал из тех же слов (`boris:<ход>`), уступает решению Бориса: становится `rejected` при любой из двух кнопок.

«Не надо» только закрывает пару.

## 6. Коммерческие обещания

Код ищет в ответе: бесплатно, в подарок, скидка, гарантия, вернём деньги, сумму («20 000 рублей»), срок («за 3 дня»). Найденное показывается в посте и пишется в раздел `## Обещание`: «Обещание Бориса: бесплатно. Сара сама такое не предлагает.» Индекс разума добавляет эту пометку к словам Бориса в образце, поэтому Сара читает их вместе. Слова Бориса в разделе `## Борис` остаются как есть.

## 7. Данные

- В журнал и лог текстов не пишется: только номера, сходство, количество пометок.
- В `core.reply_pick` и в файле только тексты с метками.
- В тестах только выдуманные данные.

## 8. Как включить

Настройка `digest.boris_replies`, по умолчанию выключена. Включается в пульте (Настройки) или так:

```sql
insert into core.setting (key, value, changed_by, changed_at)
values ('digest.boris_replies', 'true', 'system', now())
on conflict (key) do update set value = 'true', changed_by = 'system', changed_at = now();
```
