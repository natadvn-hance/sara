# Отбор по данным доски, страница заказа только для прошедших. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development. Каждый шаг: сначала падающий тест, смотрим, как он падает, потом код.

**Goal:** Сара отбирает заказы по тому, что видно на доске (как старая Сара по сниппетам, `batchTriagePrompt.js`), и открывает страницу заказа только для тех, кого Оценщик пропустил. Заявка доходит до Сортировщика сразу, а не после чтения страницы.

**Architecture:** Нода шлёт `profi.order_seen` сразу с данными доски (цена отклика 0 значит «неизвестна»). `profi.get_order` читает на странице заказа ещё и ответ `getKlientInfo` (клиент: на Профи.ру с, номер подтверждён, отзывы). Ядро в `processOrder` после Оценщика и до Аналитика зовёт `get_order` шагом DBOS под `DBOS.patch('order-page')`, кладёт цену отклика, имя и текст, сведения о клиенте на заявку; закрытая заявка получает статус `closed`, заявка с уже поданным откликом `bid_already`, без карточки. Сбой чтения не мешает: карточка идёт с данными доски, цена показана как неизвестная.

## Global Constraints

- Всё в M2 part B/C остаётся как есть: `submit_bid`, карточка, черновик. Свои правки в `cards.ts` и в сборке карточки `pipeline.ts` минимальные (параллельная сессия строит богатую карточку), перед PR rebase на main.
- Новый шаг `processOrder` только под `DBOS.patch`, `WORKFLOW_VERSION` не меняется.
- Имя клиента в модель не уходит (ADR-016). Сведения о клиенте без имени.
- Нода читает страницу только когда `can()`; тест не ходит на живой Профи.ру.
- Имена тестов начинаются с номера требования: FR-LEAD-1, FR-LEAD-2, FR-LEAD-5, ST-M1-06.
- Тексты Борису по-русски, без длинного тире.

## Tasks

1. **Разбор `getKlientInfo`** (`apps/profi-node/src/eyes/clientInfo.ts`): ответ в `ClientInfo`, терпимо к форме меток и тегов.
2. **Нода шлёт заказ доски сразу** (`eyes.ts`, `parsers.ts`, `profiParsers.ts`, `insurance.ts`): нет `waiting`, `settleOrder`, `ordersWantingPage`; страницы по ссылкам ленты только когда доска молчит.
3. **`get_order` отдаёт `client_info`** (`bid/bidTools.ts`): ответ `getKlientInfo` этого посещения страницы, имя и текст страницы, если доска их не дала; карта формы и калибровка на посещении.
4. **Подставной сайт и фальшивая нода**: `getKlientInfo` на странице заказа; `getOrder` фальшивой ноды отдаёт заданный ответ.
5. **Ядро: клиент `getOrder`** (`profi/client.ts`) и шаг `orderPage` в `processOrder`.
6. **Карточка и Аналитик**: цена неизвестна, сведения о клиенте Аналитику.
7. **Сортировщик как триаж старой Сары** (`roles/sorter/role.md`, версия выше, образцы).
