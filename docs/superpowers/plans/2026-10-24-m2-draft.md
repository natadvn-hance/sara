# M2, часть C: черновик отклика и карточка. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Каждая показанная заявка приходит карточкой с черновиком Аналитика и ценой, «Изменить» меняет текст ответом текстом или голосом, «Откликнуться» отправляет этот текст и цену (ST-M2-05, FR-LEAD-6, FR-LEAD-7).

**Architecture:** Новая роль `roles/analyst` (sonnet, P1) пишет тело отклика, скрытую потребность и цену. Приветствие, длину, тире и цену в рамках бюджета проверяет код (`apps/core/src/leads/draft.ts`). Черновик хранится на заявке (`core.lead.draft_text`, `draft_price_rub`), пишется отдельным шагом DBOS `draft` перед шагом `task` под `DBOS.patch('analyst-draft')`, чтобы старые незавершённые `processOrder` повторялись как были. «Изменить» это вопрос нового вида `edit_draft` во входящих Бориса, вне дневного лимита «почему?».

**Tech Stack:** TypeScript, Drizzle (Postgres, схема `core`), DBOS 5.3 (`DBOS.patch`), grammY, `claude -p` через шлюз, zod, vitest.

**Spec:** `docs/superpowers/specs/2026-10-24-m2-one-tap-design.md`, раздел 5.C (и разделы 1-4, 7).

## Global Constraints

- Приветствие ставит код: «{Имя}, добрый день!», если имя клиента известно, иначе «Добрый день!». Имя в модель не уходит (ADR-016).
- Приветствие плюс текст не больше 500 знаков (`BID_TEXT_MAX = 500`, длина строки JS). Слишком длинный ответ модели: один повтор с просьбой сократить.
- Формат старой Сары (`~/(SaraAI)Профи.Ру — бот /src/analyzer/prompt.js`, только чтение): понимание ситуации своими словами, один вопрос, абзацы через пустую строку; без перечня услуг, без «меня зовут», без цитат клиента, без длинного тире.
- Ответ Аналитика: `text`, `hidden_need`, `price_rub` (целое или null); цена в рамках бюджета клиента, если он указан.
- Все тексты Борису по-русски, без длинного тире (`pnpm check`).
- Имена тестов начинаются с номера требования: FR-LEAD-6 черновик, FR-LEAD-7 карточка и «Изменить», FR-LEAD-8 отклик, NFR-UX-1 тексты, NFR-REL-3 перезапуск.
- Новые события в `EVENT_TYPES`: `lead.drafted`, `draft.edited`.
- Границы части C: `apps/core/src/leads/`, `notify/cards.ts`, `learning/inbox.ts`, `learning/questions.ts`, `roles/analyst`, `apps/core/src/db/`. Вне их только строки подключения: `gateway/roles.ts` (`RoleName`), `workflows/dbos.ts` (`enablePatching`), `app.ts` (передать `onDraftText`), общие контракты (`AnalystOutput`, типы событий).

## Review Focus

1. Борис нажал «Изменить», потом «Пропустить», потом прислал текст: «Заявка уже решена, текст не поменяла», карточки нет, вопрос закрыт. Тест в Task 5.
2. Правка Бориса длиннее 500 знаков с приветствием: Сара называет число знаков, вопрос остаётся открытым, следующий короткий текст принимается. Тест в Task 5.
3. Имя клиента скрыто или заглушка («», «Клиент 3», «Заказчик»): «Добрый день!» без имени. Тест в Task 1.
4. Модель поставила цену 0 или выше бюджета, или бюджет символический («1 ₽»): поле «Стоимость услуги» пустое. Тест в Task 1.
5. Дважды «Изменить», ответ на первую просьбу: текст принимается (совпадение по номеру сообщения). Тест в Task 5.

  - `greetingOf(clientName: string): string`: первое слово имени; пусто, не буква в начале или заглушка (клиент, заказчик, пользователь, имя, аноним, скрыт) дают «Добрый день!».

  - `type Draft = { text: string; priceRub: number | null; attempts: number }`, `type DraftMiss = { text: null; reason: 'no_answer' | 'too_long' | 'not_plain'; attempts: number }`
  - `writeDraft(gw: Gateway, o: DraftSource, opts?: { correlationId?: string; causationId?: string }): Promise<Draft | DraftMiss>`: не больше 2 вызовов; второй только если первый текст длиннее 500 с приветствием или похож на JSON / `<parameter`; к входу второго добавляется пометка, почему (число знаков или «не простой текст»).
