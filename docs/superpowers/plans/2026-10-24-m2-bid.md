# M2, часть B: отклик на сайте, план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Узел Профи-MCP пишет карту формы отклика на каждом открытии страницы заказа, а `profi.get_order` и `profi.submit_bid` работают через общую вкладку аккаунта: проверяют заказ, деньги и способ оплаты, заполняют форму и подтверждают отклик повторным чтением страницы.

**Architecture:** Карта формы читается одним `page.evaluate` (`src/eyes/formMap.ts`) и пишется в `node.raw_event` (kind `dom`) из `readNewOrders`. Для отклика `startInsurance` отдаёт `inTab`: работа во вкладке идёт в той же очереди `serial`, что и минутная проверка, и только при `canNavigate`. Ответ страницы заказа (GraphQL `orders[].boOrderScreen`) разбирает `src/bid/screen.ts`, действия с формой живут в `src/bid/form.ts`, порядок проверок в `src/bid/bidTools.ts`. Подставной сайт отдаёт такой же ответ `/graphql` и рисует форму по форме настоящего.

**Tech Stack:** TypeScript, Playwright, Drizzle (схема `node`), MCP SDK, zod, vitest.

**Spec:** `docs/superpowers/specs/2026-10-24-m2-one-tap-design.md` (раздел 5.B), контракт C2 `packages/shared/src/contracts/profi.ts`.

## Global Constraints

- На настоящем Профи.ру сессия ничего не нажимает и страниц не открывает. Тесты только на подставном сайте (ADR-017).
- Карта формы: поля (`input`, `textarea`, `select`, редактируемые блоки) с подписями, заглушками, типами, видимостью; тексты кнопок; видимые строки оплаты («К оплате», «Цена отклика», кошелёк или другой способ). Ни значений полей, ни текста клиента. Ничего не нажимается.
- Порядок `submit_bid`: разрешение ядра (`verifyPermit`), открыть страницу; `has_bid` → `found_on_page: true, spent_rub: 0` без нажатий; закрыт → `ORDER_CLOSED`; кошелёк меньше суммы к оплате → `NO_MONEY`; оплата не с кошелька → `UNSAFE_PAYMENT`; заполнить «Стоимость услуги» из `price_rub` (пусто при null) и текст; нажать отправку; успех только если форма закрылась и свежее чтение ответа страницы дало `has_bid: true`, тогда `spent_rub` = сумма к оплате, `balance_after_rub` = кошелёк после. Нажато, но не подтверждено: `UNCERTAIN`.
- Вкладка общая с лентой: всё в очереди `serial`, только при `canNavigate`.
- Имена тестов начинаются с номера требования: FR-LEAD-5 (`get_order`), FR-LEAD-8 (карта и отклик), NFR-REL-4 (дубли).
- Без длинного тире «—» в коде и текстах.

## Review Focus

1. Повтор вызова с тем же `idempotency_key` после потерянного ответа: второй вызов не нажимает ничего и отдаёт тот же итог. Тест в Task 5.
2. Два вызова одновременно на один заказ: второй ждёт первого в очереди и видит `has_bid`. Тест в Task 5.
3. Вкладку нельзя трогать (живой экран смотрят, нет связи, чужой IP): отклик не нажимается, ответ понятный, не `UNCERTAIN`. Тест в Task 5.
4. Текст длиннее, чем принимает поле, или поле не приняло значение: проверка после заполнения, без нажатия. Тест в Task 4.
5. Ответ страницы не пришёл (сайт поменялся): `LAYOUT_CHANGED` без нажатий. Тест в Task 5.
