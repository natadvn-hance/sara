# M6 «Встречи и итоги»: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Борис задаёт свободное время; Сара предлагает клиенту 2-3 времени в разные дни, понимает выбор и записывает встречу без пересечений; всё, о чём Борис договорился сам, записывается одной фразой; Борис получает «📅 Встреча назначена» с брифом, утреннее сообщение и напоминание за 30 минут, после встречи отмечает итог и сумму договора, и итог сразу виден в цене договора своей недели.

**Architecture:** Новый модуль `apps/core/src/meetings/` (таблица `core.meeting` со своей машиной состояний, свободное время как настройка, процесс DBOS `meetingClock` на встречу, ежеминутные задачи, процедура созвона) и расширение `apps/core/src/analytics/` (воронка по когортам из разговоров M4, деньги из журнала, скорость, нагрузка). Итог и сумма живут на `core.deal`, сделка заводится и для клиента v1. С M4 только контракты `packages/shared/src/contracts/meeting.ts` и порты `apps/core/src/meetings/ports.ts`; подключение к движку хода M4 последним PR.

**Tech Stack:** TypeScript (Node 24), Fastify, Drizzle (Postgres 16), DBOS 5.3 (`registerWorkflow`, `runStep`, `sleep`, `recv`, `send`), grammY, zod 4, vitest, `node:sqlite` (снимок v1, только чтение), React 19 + TanStack Query + Tailwind (страница пульта), Playwright, поддельный CLI `tests/fakes/fake-claude.mjs`.

**Spec:** `docs/superpowers/specs/2026-10-25-m6-meetings-design.md` (разделы указаны в задачах), FR-MEET-1..4, FR-ANL-1..4 в `docs/spec/2026-10-22-sara-spec-v1.md`, дизайн M4 `docs/superpowers/specs/2026-10-25-m4-conversation-design.md` (после его слияния).

## Global Constraints

- Все тексты для Бориса и клиента по-русски, простым языком, **без длинного тире и среднего тире** (`pnpm check` ищет U+2014; U+2013 тоже не писать).
- Время в базе UTC; всё, что видят люди, по `Europe/Moscow` через `Intl` (как `mskParts` в `apps/core/src/learning/summary.ts`); в `apps/core/src/meetings/` нет `getHours`, `setHours`, `getDay`, `getDate`, `setDate` и `toLocale…` без `timeZone` (тест задачи 5).
- Этап сделки меняется только через `transition` или `advanceDeal` (`apps/core/src/domain/deal.ts`); состояние встречи только через `moveMeeting`; каждое изменение пишет событие.
- В событиях журнала нет телефона и слов клиента: только номера, вид, состояния, времена, сумма договора.
- Телефон клиента модель не видит; роли `scheduler` и `briefer` получают текст через шлюз с `redact.names`.
- Тексты клиенту только из таблицы 5.4 дизайна (`apps/core/src/meetings/clientTexts.ts`); в них нет ссылок и «напоминание».
- Тесты называются с номером требования: `it('FR-MEET-2: …')`. Фразы требований: FR-MEET-1 (свободное время), FR-MEET-2 (процедура созвона), FR-MEET-3 (встреча назначена, напоминания), FR-MEET-4 (итог и договор), FR-ANL-1 (воронка), FR-ANL-2 (деньги), FR-ANL-3 (скорость), FR-ANL-4 (нагрузка), FR-UI-3 (состояния экрана, 360 px, темы), FR-UI-6 (не больше двух нажатий), NFR-REL-3 (перезапуск).

## Review Focus

1. Перенос встречи, пока процесс напоминаний спит: о старом времени ничего не приходит, о новом ровно одно напоминание за 30 минут и один вопрос об итоге. Тест в задаче 9.
2. Два клиента выбирают одно и то же время одновременно: одна встреча, второй получает П5. Тест в задаче 17.
3. Клиент дописал, пока подтверждение ждало человеческой паузы M4: встреча обратно `offered`, 📅 поправлено, второй встречи нет. Тест в задаче 18.
4. Борис дважды жмёт «Договор» или отвечает на вопрос о сумме дважды, или непонятным текстом: один итог, одна сумма (последняя понятная), понятный отказ на непонятное. Тест в задаче 11.
5. Ночь и два ядра: встреча в 9:15 даёт напоминание без звука в 8:45; вопрос об итоге, созревший в 23:30, приходит утром; утреннее сообщение одно при двух тиках одновременно. Тест в задаче 10.
6. Сервер не в московском поясе: подписи и окна те же. Тест в задаче 5.
