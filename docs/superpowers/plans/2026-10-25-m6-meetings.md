# M6 «Встречи и итоги»: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Борис задаёт свободное время; Сара предлагает клиенту 2-3 времени в разные дни, понимает выбор и записывает встречу без пересечений; всё, о чём Борис договорился сам, записывается одной фразой; Борис получает «📅 Встреча назначена» с брифом, утреннее сообщение и напоминание за 30 минут, после встречи отмечает итог и сумму договора, и итог сразу виден в цене договора своей недели.

**Architecture:** Новый модуль `apps/core/src/meetings/` (таблица `core.meeting` со своей машиной состояний, свободное время как настройка, процесс DBOS `meetingClock` на встречу, ежеминутные задачи, процедура созвона с решениями по раундам хода в `core.meeting_turn`) и расширение `apps/core/src/analytics/` (воронка по неделе отклика, связь по заказу, деньги из журнала и откликов v1, скорость, нагрузка). Итог и сумма живут на `core.deal`, сделка заводится и для клиента v1. С M4 только контракты `packages/shared/src/contracts/meeting.ts` и порты `apps/core/src/meetings/ports.ts`; подключение к движку хода M4 последним PR.

**Tech Stack:** TypeScript (Node 24), Fastify, Drizzle (Postgres 16), DBOS 5.3 (`registerWorkflow`, `runStep`, `sleep`, `recv`, `send`, `startWorkflow` с номером), grammY, zod 4, vitest, `node:sqlite` (снимок v1, только чтение), React 19 + TanStack Query + Tailwind (страница пульта), Playwright, поддельный CLI `tests/fakes/fake-claude.mjs`, поддельный Telegram `tests/fakes/telegramApi.ts`.

**Spec:** `docs/superpowers/specs/2026-10-25-m6-meetings-design.md` (разделы указаны в задачах), ADR-026, FR-MEET-1..4, FR-ANL-1..4 в `docs/spec/2026-10-22-sara-spec-v1.md`, дизайн M4 `docs/superpowers/specs/2026-10-25-m4-conversation-design.md` (после его слияния).

## Global Constraints

- Все тексты для Бориса и клиента по-русски, простым языком, **без длинного тире и среднего тире** (`pnpm check` ищет U+2014; U+2013 тоже не писать).
- Время в базе UTC; всё, что видят люди, по `Europe/Moscow` через `Intl` (как `mskParts` в `apps/core/src/learning/summary.ts`); в `apps/core/src/meetings/` нет `getHours`, `setHours`, `getDay`, `getDate`, `setDate` и `toLocale…` без `timeZone` (тест задачи 5). Тихие часы только через `quietNow` (`apps/core/src/leads/cardFlow.ts`, настройка `cards.quiet_hours`).
- Этап сделки меняется только через `transition`, `transitionTx` или `advanceDeal` (`apps/core/src/domain/deal.ts`); переходы из `won` и `lost` только с `actor: 'boris'`. Состояние встречи только через `moveMeeting`. Каждое изменение пишет событие.
- В событиях журнала нет телефона и слов клиента или Бориса: только номера, вид, состояния, времена, сумма договора. Причина отказа живёт в `deal.outcome_reason`, не в `event.reason`.
- Телефон клиента модель не видит; роли `scheduler` и `briefer` получают текст через шлюз с `redact.names`.
- Тексты клиенту только из таблицы 5.4 дизайна (`apps/core/src/meetings/clientTexts.ts`); в них нет ссылок и слова «напомина».
- Тесты называются с номером требования: `it('FR-MEET-2: …')`. Фразы требований: FR-MEET-1 (свободное время), FR-MEET-2 (процедура созвона), FR-MEET-3 (встреча назначена, напоминания), FR-MEET-4 (итог и договор), FR-ANL-1 (воронка), FR-ANL-2 (деньги), FR-ANL-3 (скорость), FR-ANL-4 (нагрузка), FR-UI-3 (состояния экрана, 360 px, темы), FR-UI-6 (не больше двух нажатий), FR-NOTIF-1..4, NFR-REL-3 (перезапуск).
- Тесты первыми: падающий тест, увидеть падение, потом код. Живая модель в тестах и CI не вызывается (`FAKE_CLAUDE_OUTPUT_BY_ROLE`).
- Свой Postgres: `DATABASE_URL=postgres://sara:sara@localhost:54380/sara pnpm test`, затем `pnpm check`. Контейнер `sara-pg-m6`, в конце убрать. Контейнеры других сессий и сервер не трогать.

## Review Focus

1. Перенос встречи, пока процесс напоминаний спит: о старом времени ничего, о новом ровно одно напоминание и один вопрос об итоге. Тест в задаче 8.
2. Два клиента выбирают одно и то же время одновременно, или соглашаются одновременно: одна встреча и одно «уже не получится»; два одновременных предложения не содержат одинаковых времён. Тест в задаче 18.
3. Клиент дописал «лучше пятницу», пока подтверждение ждало человеческой паузы M4: тот же ход идёт новым раундом, прошлая запись возвращается в `offered`, 📅 поправлено, записан только новый выбор. Тест в задаче 18.
4. Борис дважды жмёт «Договор», отвечает на сумму дважды или непонятным текстом, исправляет «Отказ» на «Договор»: один итог, последняя понятная сумма, разрешённый путь этапов. Тест в задаче 12.
5. Ночь, два ядра, крах: встреча в 9:15 даёт напоминание без звука в 8:45; вопрос об итоге, созревший в 23:30, приходит утром; утреннее сообщение одно при двух тиках; крах между записью встречи и запуском часов не теряет напоминаний. Тесты в задачах 8 и 11.
6. Сделка, созданная откликом новой Сары, находится при отметке встречи: никакой второй сделки и падения на уникальности `lead_id`. Тест в задаче 4.
