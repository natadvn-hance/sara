# M2, часть A. Шлюз модели: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Шлюз `claude -p` ставит вызовы в очередь по приоритету, переживает лимит Claude (P1-P3 ждут до 6 часов, P0 идёт сразу, Борису по одному сообщению на начало и конец) и обезличивает вход модели с возвратом настоящих значений в ответ.

**Architecture:** Три маленьких модуля рядом со шлюзом: `queue.ts` (слоты по приоритету), `limit.ts` (разбор времени сброса и состояние «лимит» с проверкой ролью `probe`), `redact.ts` (метки и их возврат). `gateway.ts` собирает их в `call()`. Состояние лимита после перезапуска восстанавливается из `core.model_call`, без новой таблицы и без новых событий журнала.

**Tech Stack:** TypeScript, zod, Drizzle (Postgres), vitest (с поддельными таймерами для `limit.ts`), поддельный CLI `tests/fakes/fake-claude.mjs`.

**Spec:** `docs/superpowers/specs/2026-10-24-m2-one-tap-design.md`, раздел 5.A; FR-OPS-3, ADR-016, NFR-PRIV-2 в `docs/spec/2026-10-22-sara-spec-v1.md`; истории ST-M2-01, ST-M2-02.

## Global Constraints

- Тексты Борису ровно такие: «⏸️ Лимит Claude кончился, разбор заявок ждёт» и «▶️ Лимит Claude вернулся». Без длинного тире (`pnpm check`).
- Приоритеты `P0` < `P1` < `P2` < `P3` (P0 первым), внутри приоритета по порядку прихода. Одновременно не больше `concurrency` (по умолчанию 2) вызовов CLI, и для P0 тоже.
- Лимит: P1-P3 ждут не дольше 6 часов (`limit.maxWaitMs`, по умолчанию `6 * 60 * 60_000`), потом `limit_reached`. P0 не ждёт никогда.
- Без времени сброса в тексте CLI проверка ролью `probe` раз в 10 минут (`limit.probeEveryMs`, по умолчанию `10 * 60_000`). Со временем сброса одна проверка через 60 секунд после него (CLI показывает минуты без секунд), дальше снова раз в 10 минут.
- Метки: `[телефон N]`, `[почта N]`, `[ссылка N]` (ссылки и `@`-имена), `[имя N]`. Нумерация своя у каждого вида с 1; одно и то же значение получает одну метку.
- Обезличивание включено всегда, выключателя нет. `model_call.pseudonymized` = true у каждого вызова без слов клиента и у вызова, которому передано имя; у вызова со словами клиента, но без известного имени, false (исправлено после проверки всего M2).
- Вызывающие `createGateway` без новых полей работают как раньше (уведомитель не обязателен).
- Имена тестов начинаются с ID требования: `FR-OPS-3` (очередь и лимит), `NFR-PRIV-2` (обезличивание).
- Свой Postgres на порту 54351, не общий 54329.

## Review Focus

1. Перезапуск ядра во время лимита: второго «⏸️» нет, «▶️» приходит, когда лимит кончился. Тест в Task 4.
2. Недельный лимит со сбросом через 3 дня: вызов P2 не держится 6 часов зря, сразу `limit_reached`. Тест в Task 3.
3. Учебные задачи (предложение поправок, проверка на прошлом) не должны вставать на часы в минутном тике: для них в `app.ts` шлюз с `limitWaitMs: 0`. Тест в Task 4.
4. Цены и даты в заказе («50 000 ₽», «24.10.2026», «1500-2000») не становятся телефонами. Тест в Task 5.
5. Модель вернула метку с другим регистром или без пробела («[Телефон1]»): значение всё равно возвращается; неизвестная метка остаётся как есть. Тест в Task 5.

## Поправки после проверки (24.10.2026)

Независимая проверка ветки нашла четыре важных замечания. Все исправлены, у каждого свой тест, который сначала падал.

1. **Гонка состояния.** Лимит снимает только запуск, начатый после его начала, а включает снова только запуск, начатый после его конца. Медленный ответ из-за этого не переключает состояние.
2. **Лимит у каждой модели свой** (`guards` по `MODELS` в `gateway.ts`). Модель узнаёт лимит только из своего ответа, и проба идёт на ней же (`probe` с `model`). Причина: Борис сам тратит Opus с той же подписки, поэтому лимит одной модели не должен держать остальные. Борису по-прежнему одно «⏸️» на первый лимит и одно «▶️» на возврат последней модели (`createLimitNotice`).
3. **`stop()` не отпускает ждущих.** Задача 3 говорила обратное, это была ошибка плана. Отпущенный вызов при выкладке дал бы шагу DBOS записать пустой разбор, а ждущий просто прерывается вместе с процессом, и DBOS после перезапуска повторяет шаг.
4. **Обезличивание.** Добавлены телефоны без кода страны, с кодом города из 4-5 цифр, через точки, городские из 6 цифр. Добавлены ссылки на коротких доменах и заглавными. Ссылка не захватывает обратную косую черту, поэтому JSON остаётся целым. Имена ищутся только с настоящими падежными окончаниями, `е` и `ё` считаются одной буквой.

Попутно из мелких:
- состояние лимита читается при создании шлюза, а не при первом вызове;
- если лимит держится 6 часов, новые вызовы больше не ждут;
- далёкий сброс всё равно проверяется раз в час;
- запуск датируется своим началом, ожидание пишется в журнал (`waitedMs`);
- «Context limit reached» не считается лимитом подписки.
