# Умный чат с Сарой в теме клиента

- Дата: 07.11.2026
- Задача Бориса (06-07.11, через сессию разработки): в любой теме клиента он пишет или наговаривает, что ответить или что поправить; Сара переписывает свой черновик по его словам, нить разговора не рвётся; в теме главные сообщения Сары и клиента; после отправки клиенту обсуждение этого сообщения исчезает.
- Связано: ADR-027 (Секретарь), ADR-016 (данные клиентов метками), docs/product/telegram-forum.md, M4 (карточки разговора, «напиши: …»).

## 1. Что видит Борис

1. В теме клиента пришёл черновик Сары (карточка 💬 с «Отправить»), или черновика нет вовсе.
2. Борис пишет в теме: «короче, без цены, предложи созвон в четверг» или наговаривает голосовое.
3. Под голосовым Сара тихо ставит расшифровку в свёрнутой цитате (🎙, раскрывается нажатием).
4. Сара отвечает в той же теме одним сообщением: новый вариант для клиента с кнопками «Отправить» и «Изменить», а если нужно, короткая строка для Бориса над ним. Старый вариант из этого же обсуждения теряет кнопки, чтобы «Отправить» в теме была одна.
5. Борис правит дальше сколько угодно раз. Когда он нажимает «Отправить», текст уходит клиенту обычным путём (outbox, проверка чата, «клиент дописал» и прочие проверки M4 не меняются).
6. Как только сообщение дошло до клиента (отправка нажатием подтвердилась) или тема показала наше сообщение обычным постом «Мы» (Борис ответил сам с сайта), бот удаляет обсуждение этого сообщения. В теме остаются посты клиента, наши отправленные посты и карточки Сары.

Ничего не уходит клиенту без нажатия «Отправить». Команды «беру сам», «верни», «закрой», «да» и «напиши: …» работают, как раньше; рассказ о прошедшем созвоне идёт в карточку встречи, как раньше; ответ на «Изменить» остаётся дословным вариантом Бориса.

## 2. Что считается обсуждением сообщения

Обсуждение это сообщения темы, которые бот записал в таблицу `core.topic_discussion` в ходе чата в теме:

| Вид | Что это |
|---|---|
| `boris` | Сообщение Бориса (текст или голос), которое ушло чату в теме |
| `transcript` | Расшифровка его голосового |
| `sara` | Ответ Сары Борису в этом чате (строки для него, вопросы) |
| `version` | Промежуточный вариант для клиента с кнопками, предложенный чатом |

Не обсуждение и не удаляется никогда: посты клиента, наши отправленные посты, первый пост темы, карточка встречи, карточка черновика Сары 💬, карточки откликов, напоминаний и шагов, всё, что не записано в `topic_discussion`.

Обсуждение сообщения это все неудалённые записи разговора, сделанные до того, как тема показала наше отправленное сообщение. Отправилось ли сообщение кнопкой из обсуждения или Борис ответил сам с сайта, неважно: после любого нашего сообщения в чате обсуждение до него закрыто.

## 3. Агент

- Роль `topic-chat` (Opus, усилие medium), один запуск `claude -p` на ход, как Секретарь (`buildConverseArgs`): в теме один ход за раз, слова, пришедшие во время хода, идут следующим ходом вместе.
- Вход хода: время, заказ (название, текст заявки, имя на заказе), последние 30 сообщений чата Профи.ру, открытый черновик (текст), указания Бориса по этому клиенту (`conversation.boris_note`), разговор в теме до этого (записи `topic_discussion` этого обсуждения со словами), новые слова Бориса. Данные клиента идут метками (ADR-016), как у Секретаря.
- Инструменты MCP-сервера `sara` по адресу `/internal/topic-chat/mcp` (только 127.0.0.1, ключ хода):
  - `chat` (весь чат этого клиента), `order` (заявка целиком), `client` (карточка клиента пульта: указание, заметки Лоры, встречи), `meeting` (ближайшая встреча), `mind` (записи разума по словам);
  - `propose` (новый вариант для клиента: показывает карточку с «Отправить» и «Изменить», ничего не отправляет);
  - `remember` (указание Бориса по этому клиенту дописывается в `boris_note` с датой: его видят все следующие ходы и переговорщик, после уборки обсуждения тоже).
- Веб: только этой роли разрешены встроенные `WebSearch` и `WebFetch` (Борис, 07.11; ADR-027 дополнен). Файлов и команд нет. Факт для клиента только с источником: роль пишет Борису, откуда он, а без источника в черновик факт не идёт.
- Защита подписки та же, что у Секретаря: общий предел ходов в сутки `secretary.turns_per_day` (ходы чата в теме идут в него), ход не дольше 4 минут, не дороже 3 долларов, при лимите Claude Борис в теме получает строку о лимите, черновик не трогается.

## 4. Голос

Сара не держит вторую модель: голосовые распознаёт служба Лоры `lora-voice-stt` (faster-whisper small int8) на том же сервере.

- Ядро кладёт голосовое в общую папку `/srv/voice-share/in/` (смонтирована в контейнер ядра по тому же пути) и спрашивает сокет `/srv/voice-share/stt.sock`: одна строка JSON `{"op":"transcribe","path":...}`, ответ `{"ok":true,"text":...}` (протокол Лоры, `voice_server.py`). Файл удаляется сразу после ответа. Копия получает группу папки (`chown` на `gid` папки, владелец прежний) и права 640: `copyFile` в Node переносит владельца и группу источника (gid 0 в контейнере ядра), и служба Лоры (пользователь `lora`, группа `voice-share`) получала `Permission denied` на каждом голосовом (12.11.2026).
- Сокет в общей папке это прокси `socat` от имени `lora` к её `~/.cache/lora-voice/stt.sock`: код Лоры не меняется, модель одна.
- Включается переменной `SARA_VOICE_SOCKET`; без неё остаётся whisper.cpp в образе (разработка и тесты).
- Нет сокета, служба молчит дольше 2 минут или ответ пустой: Сара в теме отвечает «Не расслышала голосовое, напиши текстом, пожалуйста», ход не запускается.
- Шаги на сервере: раздел 7.

## 5. Уборка

- Когда отправка подтвердилась (`convSend`, «Отправила клиенту») или тема показывает наше сообщение (`showClientWords`, пост «Мы»), бот удаляет обсуждение до него: `deleteMessage` для каждой записи, свежее 47 часов.
- Нужно: бот админ группы с правом `can_delete_messages`. Без права или для записи старше 47 часов (Telegram удаляет только за 48 часов) пост бота сворачивается в одну строку без кнопок «· обсуждение черновика»; сообщения Бориса бот изменить не может, они остаются.
- В журнал идёт событие `topic.discussion_cleared` с номерами удалённых и свёрнутых постов (только номера, без слов).
- Удаление никогда не ломает отправку и показ поста «Мы» и не повторяется: запись получает `cleared_at`, слова записи стираются.
- Слова обсуждения (его, расшифровка, Сарины) лежат в записи, пока обсуждение живо: следующий ход читает разговор целиком. После уборки остаются только номера постов.

## 6. Что не входит

- Чат в общей теме и в теме «Заявки»: там остаётся Секретарь.
- Голосовые ответы Сары (отдельная задача).
- Уборка карточки черновика 💬: в ней слова клиента, её судьба решается отдельно с Борисом.

## 7. Шаги на сервере (делают ведущая сессия и Борис, sudo)

```bash
sudo groupadd --system voice-share
sudo usermod -aG voice-share lora
sudo install -d -o root -g voice-share -m 2770 /srv/voice-share /srv/voice-share/in
sudo apt-get install -y socat
```

Юнит `/etc/systemd/system/sara-voice-proxy.service`:

```ini
[Unit]
Description=Sara's door to Lora's speech recognition
After=lora-voice-stt.service
Requires=lora-voice-stt.service

[Service]
User=lora
Group=voice-share
UMask=0007
ExecStartPre=/bin/rm -f /srv/voice-share/stt.sock
ExecStart=/usr/bin/socat UNIX-LISTEN:/srv/voice-share/stt.sock,fork,mode=0660 UNIX-CONNECT:/home/lora/.cache/lora-voice/stt.sock
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now sara-voice-proxy
```

В `infra/compose.prod.yml` (уже в этом PR) ядро получает том `/srv/voice-share:/srv/voice-share` и `SARA_VOICE_SOCKET: ${SARA_VOICE_SOCKET:-}`. Чтобы включить, в `/opt/sara/.env`:

```
SARA_VOICE_SOCKET=/srv/voice-share/stt.sock
```

Ядро в контейнере работает от root, поэтому сокет 0660 ему открыт; файлы в `in/` наследуют группу `voice-share` и читаются Лорой. Бот в группе Бориса должен быть админом с правом удалять сообщения.

Проверка после выкладки: голосовое в теме клиента, в журнале ядра нет `voice socket`, в теме появилась расшифровка.
