# Как вести разработку

Разработку ведут сессии Claude Code, решения принимает Борис. Документ
описывает поток работы так, чтобы любая новая сессия начала с того же
места.

## 1. Поток работы

```
бэклог → история по DoR → ветка → тесты → код → пул-реквест →
CI → проверка кода → слияние в main → выпуск → тень → приёмка Бориса
```

1. Взять верхнюю историю текущей вехи, у которой выполнен DoR
   (`docs/quality/definition-of-ready-and-done.md`).
2. Ветка `st-m0-04-event-journal` от свежего `main`.
3. Сначала тест, который падает; потом код; потом уборка.
4. Пул-реквест по шаблону `.github/pull_request_template.md`.
5. CI: форматирование, линтер, типы, тесты, сборка, поиск секретов,
   проверка длинного тире, трассируемость.
6. Проверка кода отдельной сессией (навык requesting-code-review).
7. Слияние в `main` только с зелёным CI. Ветка удаляется.

## 2. Коммиты

Conventional Commits на английском:

| Префикс | Когда |
|---|---|
| `feat:` | новая возможность |
| `fix:` | исправление |
| `docs:` | документы |
| `test:` | только тесты |
| `refactor:` | переделка без изменения поведения |
| `chore:` | инструменты, зависимости |

`feat!:` или строка `BREAKING CHANGE:` для ломающих изменений контракта
(нужен ADR).

## 3. Выпуски

release-please собирает пул-реквест выпуска с номером версии и
`CHANGELOG.md`. После слияния собираются образы, выкладка идёт командой
`sara-deploy <версия>` (`docs/architecture/deployment.md`). Борису
уходит «Что нового» по шаблону `docs/templates/release-notes.md`.

## 4. Документы

| Что меняется | Что обновить |
|---|---|
| требование | спецификация, трассируемость |
| форма данных между частями | `docs/architecture/contracts.md` и схема zod |
| таблица или поле | `docs/architecture/data-dictionary.md` |
| решение, которое трудно отменить | новый ADR |
| новый сбой | `docs/ops/runbooks.md` |
| новая внешняя связь или данные | `docs/architecture/threat-model.md` |
| крупная фича на несколько вех | RFC по шаблону `docs/templates/rfc.md` |
| сбой S1 | разбор по шаблону `docs/templates/postmortem.md` |
| конец блока работы | документ передачи дел в `docs/handoff/` |

## 5. Локальный запуск

Появится в M0: Docker, Node 24, pnpm; `pnpm install`, `pnpm dev`,
`pnpm test`. Бот для разработки и токен Claude вводятся в мастере запуска.
