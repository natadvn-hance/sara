# Копии базы

| Где | Что |
|---|---|
| Основной сервер 143.246.42.121 | `backup.sh` ночью (cron, root): `pg_dump`, шифрование `age` открытым ключом `/etc/sara/backup.pub`, файл в `/var/backups/sara` (3 дня) |
| Основной сервер | пользователь `backup-pull`: ключ сервера копий с принудительной командой `serve.sh` (только `list`, `get`, `ack`), только с адреса 84.38.182.236 |
| Сервер копий 84.38.182.236 (Санкт-Петербург) | `pull.sh` (cron, `sara-backup`): забирает новые копии, хранит 30 дней, подтверждает каждую по sha256 |
| Основной сервер | `restore-check.sh` раз в неделю: расшифровывает последнюю копию, восстанавливает в пустую базу, сверяет sha256 с подтверждением сервера копий (SLO-7) |

Почему копии забирает сервер копий, а не основной их отправляет: связь из
Нидерландов к серверу в Петербурге не проходит, а из Петербурга наружу
проходит (проверено 23.10.2026).

Ключ расшифровки `/etc/sara/backup.key` есть только на основном сервере:
на сервере копий лежат только зашифрованные файлы. Если основной сервер
погибнет вместе с ключом, копии не расшифровать, поэтому копию ключа
Борис хранит у себя (менеджер паролей).
